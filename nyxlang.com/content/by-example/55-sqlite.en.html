std/sqlite provides SQLite3 bindings loaded at runtime via dlopen. sqlite_open(":memory:") creates an in-memory database, sqlite_exec runs DDL/DML statements, and sqlite_query returns rows as arrays of strings. No external dependencies are needed — SQLite is bundled with most operating systems.

sqlite_open returns an opaque database handle (*int, NULL on failure). The special path ":memory:" creates a temporary in-memory database that is discarded when the handle is closed. For persistent storage, pass a file path like "data.db".

sqlite_query returns an array of rows, where each row is an array of string values — not because SQLite stores them that way (it has storage classes: NULL, INTEGER, REAL, TEXT, BLOB), but because the binding reads every column with sqlite3_column_text, which converts whatever is stored into text. Column order matches the SELECT clause. sqlite_exec is used for statements that don't return data (CREATE, INSERT, UPDATE, DELETE).
