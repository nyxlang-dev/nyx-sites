Lanzar un programa externo

try_spawn(argv, opts) arranca un proceso hijo y devuelve un Child. argv es un Array: no hay shell de por medio, así que no hay comillas, * ni $VAR que escapar. spawn_opts() deja stdin, stdout y stderr heredados, de modo que el hijo escribe en la misma terminal que el padre. try_child_wait bloquea hasta que el hijo termina y devuelve su código de salida.

// Lanzar un programa externo — std/process
// Run an external program — std/process
//
// try_spawn lanza el hijo SIN fork, así que el mismo código es portable.
// argv es un Array (sin shell: nada de comillas ni `*`), y si el
// programa no existe el lanzamiento da Err(not_found) en vez de un hijo que
// sale con 127.
//
// Nota: los builtins crudos fork/execvp/waitpid/dup2/pipe_new/kill_process
// siguen disponibles en posix tal como siempre; donde no hay fork, el
// compilador los rechaza y apunta a std/process. Esta receta usaba fork +
// execvp + waitpid.
// EN: raw fork/execvp/waitpid remain available on posix; std/process is the
// portable replacement.

import "std/process"

fn main() -> int {
    // Todo heredado: el hijo escribe en la misma terminal que el padre.
    let opts: SpawnOpts = spawn_opts()
    match try_spawn(["echo", "hello from child"], opts) {
        Result.Ok(c) => {
            if child_pid(c) > 0 { print("parent: spawned child") }
            match try_child_wait(c) {
                Result.Ok(code) => { print("parent: child exited with " + int_to_string(code)) }
                Result.Err(e) => { print("wait failed: " + e.msg) }
            }
        }
        Result.Err(e) => { print("spawn failed: " + e.msg) }
    }

    // Un programa inexistente falla al lanzar.
    match try_spawn(["nyx-no-such-program-xyz"], opts) {
        Result.Ok(_c) => { print("unexpected: it ran") }
        Result.Err(e) => { print("not found: " + e.kind) }
    }
    return 0
}
Salida ilustrativastdout
hello from child
parent: spawned child
parent: child exited with 0

Cómo funciona

El padre y el hijo escriben a la vez, así que el orden de las dos primeras líneas puede cambiar de una corrida a otra; el código de salida siempre llega después, porque try_child_wait espera al hijo.

Un programa que no existe falla al lanzar: try_spawn devuelve Err con kind not_found y e.stage == "exec". Con fork + execvp crudos el padre no veía ningún error y el hijo salía con 127; si tu código dependía de eso, traduce not_found a 127 por tu cuenta.

Los builtins crudos fork, execvp y waitpid siguen disponibles en posix, sin cambios. std/process es el camino portable, y no necesita cuidados con el recolector de basura: no hay una copia del padre hecha con fork.
