The same program can be built for an aarch64 Android device without touching the code. The result is a bionic PIE (API 24, linker64) with libgc and OpenSSL linked statically, which you copy to the device and run inside Termux, with no proot.

arquitectura: aarch64 suma 1..100 = 5050

There are three steps. First, once: bash scripts/build_android_deps.sh ~/.cache/nyx-android-deps prepares the NDK r27c sysroot, Boehm GC 8.2.12 and OpenSSL 3.6.5 for bionic (about 5 minutes and 58 MB, plus 664 MB of zip cache; NYX_ANDROID_DEPS changes the directory). Second, from a project with nyx.toml, nyx build --target aarch64-linux-android writes target/aarch64-linux-android/<name>; it needs clang 19 or newer and lld, and does not use the NDK tools. Third, copy it with scp, adb push to /data/local/tmp or Termux's shared storage, and run it. The program itself prints the architecture (via uname -m) and the sum 1..100, and runs the same natively.

Limits: nyx run --target aarch64-linux-android does not execute anything and gives a clear error; copy the binary to the device. TLS looks for CAs in SSL_CERT_FILE / SSL_CERT_DIR, then $PREFIX/etc/tls/cert.pem (Termux), then /system/etc/security/cacerts/; Android user CAs are not read yet. SQLite is loaded with dlopen from $PREFIX/lib/libsqlite3.so (in Termux, pkg install libsqlite). The temp directory is $TMPDIR, falling back to /data/local/tmp. NYX_ANDROID_STATIC=1 builds a static binary only to test on arm64 Linux; it has no dlopen, so std/sqlite and zlib inflate do not work, and it is not a distribution artifact. To load Nyx from an app instead of Termux, see the shared library recipe (157).
