Capturar stdout y stderr de un hijo

try_spawn(argv, opts) arranca el hijo con cada flujo como un Stdio (heredado, nulo, pipe, archivo o fd). argv es un Array, así que no hay shell: ni comillas, ni *, ni $VAR que inyectar. Con stdout y stderr en Stdio.Pipe, try_child_collect drena los dos a la vez y espera al hijo, y devuelve ChildOutput { stdout, stderr, code }.

// Nyx by Example: capturar stdout y stderr de un hijo con std/process.
//
// std/exec pasa el comando por el shell; std/process lo lanza sin shell
// (argv es un Array: nada de comillas, `*` ni `$VAR`, así que no hay nada que
// inyectar) y con la misma API en todas las plataformas.
//
//     o.stdout = Stdio.Pipe;  o.stderr = Stdio.Pipe
//     try_spawn(argv, o) -> Result<Child, Error>
//     try_child_collect(c) -> Result<ChildOutput, Error>
//     ChildOutput { stdout: String, stderr: String, code: int }
//
//   - collect lee stdout y stderr A LA VEZ hasta EOF y espera al hijo: leer
//     "stdout entero y luego stderr" se cuelga si el hijo llena el pipe de
//     stderr mientras tanto.
//   - Un programa que no existe falla AL LANZAR con Err(not_found): no hay un
//     hijo que salga con 127.
//   - Bloqueante: con muchos hijos, un `spawn` por hijo.

import "std/process"
import "std/error"

// Corre argv; si sale con código distinto de 0 devuelve Err con su stderr.
fn correr(argv: Array) -> Result<String, String> {
    var o = spawn_opts()
    o.stdout = Stdio.Pipe
    o.stderr = Stdio.Pipe
    match try_spawn(argv, o) {
        Result.Ok(c) => {
            match try_child_collect(c) {
                Result.Ok(r) => {
                    if r.code != 0 {
                        return Result.Err("falló con código " + int_to_string(r.code) + ": " + r.stderr.trim())
                    }
                    return Result.Ok(r.stdout)
                }
                Result.Err(e) => { return Result.Err("collect: " + e.msg) }
            }
        }
        Result.Err(e) => { return Result.Err("no se pudo lanzar (" + e.kind + ")") }
    }
    return Result.Err("inalcanzable")
}

fn main() -> int {
    match correr(["echo", "hola desde std/process"]) {
        Result.Ok(s) => { print("ok: " + s.trim()) }
        Result.Err(m) => { print("error: " + m) }
    }
    // Falla con código y motivo en stderr.
    match correr(["sh", "-c", "echo motivo >&2; exit 3"]) {
        Result.Ok(s) => { print("ok: " + s) }
        Result.Err(m) => { print("error: " + m) }
    }
    // Programa inexistente.
    match correr(["nyx-no-such-program-xyz"]) {
        Result.Ok(s) => { print("ok: " + s) }
        Result.Err(m) => { print("error: " + m) }
    }
    return 0
}
Salidastdout
ok: hola desde std/process
error: falló con código 3: motivo
error: no se pudo lanzar (not_found)

Cómo funciona

Un programa que no existe falla al lanzar con Err de kind not_found: no hay un hijo que salga con 127. Leer "todo stdout y luego stderr" puede colgarse si el hijo llena el pipe de stderr mientras tanto; try_child_collect lo evita. Las llamadas bloquean el hilo: con muchos hijos, un spawn por hijo. try_child_signal existe solo en posix; try_child_kill anda en todas partes. Los builtins crudos fork/execvp siguen disponibles en posix.
