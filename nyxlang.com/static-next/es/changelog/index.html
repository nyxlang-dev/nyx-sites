0.42.0 2026-11-08

MINOR: destinos nuevos de nyx build armados desde Linux — Android/Termux (aarch64-linux-android, PIE de bionic que corre sin proot) y el .exe de Windows x86_64 (win-cross) —, nyx build nativo en Windows y un .exe que corre como servicio, std/rsa con certificados X.509, imports cíclicos que funcionan en build, check y [lib], y los silently-wrong que nyxerp encontró en uso real: una casilla de un Array sin tipo leída como struct/enum (NYX2022 en vez de SIGSEGV o basura), crc32_bytes de un String y for x in xs sin <T>.

Migración: un programa que pasaba una casilla de un Array sin tipo con otra cosa adentro (una fila, un String) a un parámetro struct/enum ahora aborta con NYX2022 en vez de dar SIGSEGV o leer basura: anotar Array<T> o convertir la casilla antes de pasarla. NYX_SLOT_CHECK=off apaga la guarda mientras se migra.

Fixed

  • crc32_bytes(xs[i]) con una casilla de un Array sin tipo emite IR válido (el arreglo de crc32 de String del 11-05 numeraba el temporal del resultado antes que el inttoptr de la casilla; lo caza run_builtin_arg_opaco.sh). La rama de crc32 sale de codegen_call_expr a emit_crc32_bytes: en línea había subido su marco -O0 1760 B por encima del techo; ahora queda en 472064 B (techo bajado en run_stack_frame_audit.sh).
  • Una casilla de un Array sin tipo que va a un struct o enum se lee por su tag: NYX2022 en vez de SIGSEGV o basura (silently-wrong, fricción nyxerp 20261108). Pasar a[0] (o la variable de un for sobre a) a un parámetro Caja o Valor compilaba y pasaba nyx check; en ejecución un struct daba SIGSEGV y un enum leía el discriminante de otra estructura y el match no entraba en ningún brazo (salida vacía, exit 0). Ahora, en los destinos argumento de llamada o de método, let x: T, x = …, return y for p in a, si el tag de la casilla prueba que no es un struct/enum (int, String, float, bool, Array, Map) el programa aborta con NYX2022 nombrando el tipo esperado y el encontrado (rc 1). UNKNOWN y PTR pasan: el patrón legítimo a.push(caja); leer(a[0]) no cambia (los 5 stacks verdes). Se apaga con NYX_SLOT_CHECK=off. Sin cubrir todavía: el campo de un struct literal (S { c: a[0] }) y for p: Caja in a (ficha en TASKS.md). Tests: test-541, el error test slot-sin-tipo-leido-como-struct-enum-abort y ai-first 53.
  • Imports cíclicos: dos módulos que se importan entre sí (a ↔ b), o un módulo que importa de vuelta al principal, compilan y se chequean igual en nyx build, en nyx check sobre cualquiera de los archivos y con [lib] modules (fricción nyxerp 20261106). Ya eran válidos por diseño (el resolver inlinea cada ruta una sola vez), pero había dos bugs al costado: el escaneo de tipos de un import leía los campos de un struct de UNA línea en las líneas siguientes, y con el ciclo daba NYX1017/NYX1032 falsos («missing fields: pub»); y el archivo principal no contaba como ya importado, así que nyx check src/m/a.nx lo reinlineaba y daba NYX1040. De paso, pub struct Id(int) en un módulo importado exportaba el nombre «Id(int)» y rompía el parse (NYX0101). Guardas: Check R de run_tooling_gates.sh (+5) y 3 casos de ciclo en run_lib_modules.sh.
  • crc32_bytes(s) con un String daba un número distinto por llamada (silently-wrong, fricción nyxerp del 2026-11-05, editor visual del sitio). El builtin esperaba un Array de bytes, el checker no miraba el tipo y codegen entregaba el %nyx_string* como si fuera un array: el runtime leía el struct del String como array y recorría basura. Ahora un String va a nyx_crc32_string (el CRC-32 de sus bytes, misma tabla; "123456789" → 3421780262), un Array sigue como antes, y un int/float/bool es NYX1031 con pista. Tests 531 y test-nyx1031-crc32-bytes-int; línea en LLM.md.
  • nyx build barre sus temporales huérfanos (compiler/build.nx). Si mataban un build (Ctrl+C, KILL, timeout externo) no se llegaba al borrar_arbol final y su nyx_libs_<pid>_…/nyx_build_<pid>_… quedaba en $TMPDIR para siempre (48 MB en un caso medido el 2026-11-05; en el servidor /tmp es tmpfs). Ahora tmp_dir_propio borra antes los directorios de esa forma exacta cuyo PID ya no existe (kill_process(pid, 0), y /proc en Linux), en Nyx puro para que valga en Windows; lo de un PID vivo y lo que no tiene la forma no se toca. Misma receta que nyx test. Tres checks nuevos en run_build_manifest.sh (37). Cierra la ficha BAJA «nyx build interrumpido con Ctrl+C».
  • nyx test respeta $TMPDIR y barre sus propios huérfanos (compiler/test.nx). Los cuatro mktemp decían /tmp a secas: una suite que exportaba TMPDIR para no llenar el tmpfs (nyxerp) seguía dejando el binario de cada archivo en la RAM de la máquina, y si mataban nyx test (KILL, timeout externo) el trap del sh por archivo no alcanzaba y el directorio quedaba para siempre (el 2026-10-26: 30 restos y ~1,3 GB de swap en páginas de /tmp). Ahora la base es $TMPDIR (o /tmp), cada temporal lleva el PID del dueño (nyx_test_<pid>_XXXXXX, nyx_test_src_, nyx_test_libs_, nyx_cov_) y la corrida siguiente borra los de PIDs muertos; lo de un PID vivo y los nombres del formato viejo no se tocan. Los paths del script generado van entre comillas (un TMPDIR con espacio fallaba). Un TMPDIR inexistente da un error claro en vez de un FAIL mudo. Cuatro checks nuevos en run_tooling_gates.sh (38). Cierra la ficha BAJA del 2026-10-26.
  • for x in xs sobre un Array sin <T> lee cada casilla por su tag, como ya hacía xs[i] (silently-wrong, reporte de nyxerp del 2026-11-04 al adoptar el fix de get_or). Cuando codegen no conocía el tipo del elemento (Array pelado, m.get_or(k, []), literal mixto), x era int y print(x) / "v=" + x mostraban la dirección del String sin error. Ahora codegen_for reescribe el cuerpo para que cada x sea __arr[__idx] sobre dos variables ocultas (walker de licm.nx, for_sustituir_var), y todos los consumidores pasan por codegen_index_access, que consulta el tag. No aplica si el cuerpo re-liga x, muta el array recorrido o tiene fns anidadas (queda el camino viejo); NYX_FOR_SLOT=off lo apaga. De paso, let a: Array = [1, "dos"] ya no se infiere Array<int> por el primer elemento: usa el tipo común (tipo_comun_de_literal, como el for sobre literal desde 0.36.0) y un literal mixto queda Array pelado (cierra la ficha BAJA del 2026-07-26). Test ai-first/52, gotcha for-untyped-slot-by-tag.
  • m.get_or(k, []) con un Array (o un Map, o un struct) guardado como valor ya no produce IR inválido cuando el resultado se usa sin anotar (for x in m.get_or(k, []), pasarlo como argumento, encadenar .length()). El helper de get_or devolvía i64 para todo default que no fuera String ni float, y solo sobrevivía detrás de un let v: Array = … (convierte por el tipo declarado); sin la anotación clang rechazaba el IR («defined with type 'i64' but expected 'ptr'», reporte de nyxerp del 2026-11-04, variante del caso de ai-first/49). Ahora el resultado tiene el tipo del default, igual que ya pasaba con float (y el for sobre él lee por tag: bullet anterior). Test ai-first/51.
  • install.ps1 falla en el acto si un proceso retiene la instalación anterior (.nyx.old en uso) en vez de descubrirlo tras un minuto de compilar y enlazar; el mensaje nombra el paso que falló y «your current install was not changed»; y avisa de NYX_HOME cuando se instala con -Prefix distinto de %USERPROFILE%\.nyx, porque el driver no busca su instalación junto al ejecutable (ficha ALTA en TASKS.md). Parche de la laptop, W6 Task 8 ronda 1.

Fixed

  • Una closure creada en un bucle ve la variable de SU iteración (semántica de Go 1.22): un let/var del cuerpo tenía UN campo en el entorno compartido, así que cuatro closures guardadas en un Array y llamadas después del bucle leían las cuatro la última (3 3 3 3 en vez de 0 1 2 3), sin error. Ahora cada iteración tiene su instancia (un box GC por iteración, solo en funciones con una fn anidada dentro de un bucle) y cada lambda/spawn recibe un marco con los boxes de esa vuelta; el cuerpo y las closures de la iteración comparten la instancia (un var mutado después de crear la closure lo ve ella) y las variables de afuera del bucle siguen compartidas. Con eso spawn dentro de un bucle y la variable de un for dejan de ser NYX1044; siguen siéndolo el nombre repetido y los bindings de match. Observable: un programa que daba 3 3 3 3 pasa a dar 0 1 2 3. tests/ai-first/48-closure-por-iteracion.
  • a[i] == b[j] entre dos Array sin tipo compara los Strings por contenido: ningún lado aportaba tipo y se comparaban las casillas crudas, así que el mismo texto en dos arrays distintos daba false sin error. nyx_slot_eq (runtime) decide por los tags: dos casillas String por contenido, el resto crudo (5 contra "5" sigue false). Con Array<T> decide el tipo estático, como antes. tests/ai-first/47-casilla-igual-casilla.
  • m.insert(a[0], a[1]) en un Map<String> con a: Array sin tipo guarda el valor como String: la casilla llegaba como i64 crudo, el Map se re-registraba como Map<int> y print(m.get(k)) imprimía el puntero sin error (fricción de nyxerp). emit_map_insert_i64 respeta el tipo de valor ya registrado. Un var m: Map sin anotar sigue fichado. tests/ai-first/46-map-insert-casilla-string.

Ahora usan tls_upgrade_fd_verified_system / tls_connect_verified_system, como ya hacía std/imap. Verificado contra smtp.gmail.com en 587 y 465: antes fallaban los dos, ahora verifican. El autofirmado sigue rechazado (test-stdlib-07, caso d). El rodeo ya no hace falta; una CA privada por conexión queda fichada.
  • Una casilla de un Array sin <T> pasada directo a un parámetro struct, o usada como clave de Map, ya funciona (fricción nyxerp, 2026-10-17). texto(hs[0]), con fn texto(h: Hoja), pasaba el i64 crudo de la casilla donde la función esperaba el struct por valor. El resultado era «GC heap exhausted» o, en otro programa de nyxerp, la función recibía otro elemento. m.insert(pares[0], pares[1]) usaba el i64 como puntero de la clave y clang rechazaba el IR. En los dos casos nyx check daba verde. Ahora la casilla se convierte al struct del parámetro (inttoptr + load, como en let h: Hoja = hs[0]), y la clave de un método de Map que sale de una casilla se lee como String. El propio compilador tenía el mismo patrón en cg_tipo_duplicado(decls[i], …), que andaba de casualidad por la convención de llamadas de aarch64. ASTNode queda afuera: en una casilla es un Array y no un puntero. Regresión: tests/ai-first/40-casilla-sin-tipo-como-argumento.nx y gotcha untyped-slot-as-argument.
  • nyx check rechaza una variante de enum que no existe (NYX2012) (fricción nyxerp, 2026-10-17). PdfFont.Zzzz pasaba el chequeo en verde y recién el codegen lo rechazaba, con un mensaje que pedía una anotación de tipo. Ahora es NYX2012, con «did you mean» si hay una variante cercana, tanto para enums locales como importados. No se valida cuando el nombre corresponde a una variable o a un parámetro. Casos test-nyx2012-variante-{inexistente,importada}.
  • Escapes de String: \xNN y \u{…} valen lo que dicen, y un escape desconocido avisa (NYX1045) . Antes el lexer conocía solo \n \t \\ \" \r \0 y cualquier otro escape perdía la barra en silencio: "\x41" valía x41, "\u{0}" valía u{0} y '\x41' imprimía 41. Había tres casos reales, todos equivocados sin que nadie lo notara: el centinela "\u{0}" de la configuración de nyxerp, el separador "\x1F" de la clave de DISTINCT de nyx-db (y su copia en venezuelainfo), y las secuencias ANSI "\x1b[…" del ejemplo de nyx-edit. Con este arreglo los tres valen lo que quisieron decir sin tocar su código. \' y \$ ("\${x}" es ${x} literal) quedan documentados. Un \x o \u{…} malformado es error de lexer con línea y columna. Cualquier otro escape es warning [NYX1045] y pasa a error en 0.37.0. Los cuatro caminos del lexer que leían escapes, que eran cuatro copias del mismo if, ahora pasan por una sola función. test-494-escapes-hex-unicode, siete casos test-nyx1045-* y gotcha string-escapes.
  • CAPABILITIES.md ya no esconde 34 módulos de la stdlib en «Otros». La tabla curada module_category de compiler/build.nx no tenía 34 de los 78 módulos, entre ellos serve, postgres, error, math, map, router, template, xlsx, pdf e image. Todos tienen ahora categoría, y se suman dos categorías nuevas: «Núcleo» (error, prelude) e «IA & LLM». «Otros» queda solo para builtins sin tema. Guarda nueva (d) en run_capabilities_test.sh: falla si un módulo de std/ cae en «Otros», así que un módulo nuevo entra a la tabla en el mismo commit que lo crea.
  • El compilador ya no copia de forma cuadrática: un archivo de prueba grande de nyxerp compila 9 veces más rápido (fricción nyxerp, 2026-10-17: ~42 s por archivo de nyx test). La medición por fase mostró que el tiempo crecía más rápido que el IR, y un perfilador de muestreo que el 81% era el GC, provocado por concatenaciones que recopiaban todo lo acumulado: las constantes de texto en generate_llvm, las declaraciones de módulo en resolve_source, y el prefijo de símbolo de cada módulo recalculado carácter por carácter en cada llamada sin calificar. Ahora van con StringBuilder, los prefijos se calculan una vez (ctx.alcances[3]), la búsqueda de una función entre los módulos se memoriza (ctx.alcances[4], con la versión del conjunto en la clave), extract_exports no recorta las líneas que no pueden exportar nada y scan_module_types no relee un módulo ya escaneado. La huella de [lib] en nyx_build tenía el mismo patrón (todo = todo + … sobre el cierre de imports): un nyx_build libs sin cambios, que nyx test corre en cada archivo, bajó de 5,7 s a 2,0 s en nyxerp. El IR sale idéntico byte a byte. Medido: 105,6 s → 11,2 s y 822 → 642 MB en el archivo más grande; 3,5 s → 1,6 s en uno mediano. Spike: docs/design/spikes/2026-10-17-test-sin-repetir-medicion.md.
  • Operadores entre primitivos de clases distintas: NYX1010 en vez de SIGSEGV o IR inválido. El chequeo dejaba pasar aritmética y comparación entre cualquier par de tipos. La matriz medida el 2026-10-17 (cuatro tipos por lado, nueve operadores) mostró que solo existen números con números, String + x, ==/!= entre dos String o dos bool y el orden entre dos String; el resto moría con SIGSEGV al ejecutar la línea (5 + "a", 5 == "5", "a" < 5) o daba IR inválido que recién rechazaba clang (x * "dos", 2.5 + "a", true + 1). Lo segundo nunca produjo un binario y es error ya; lo primero compilaba, así que por la regla 7 de docs/VERSIONING.md es warning [NYX1010] en 0.36.x y error en 0.37.0. Nyxerp (539 archivos) no tiene ningún caso. Tests: test-493-operadores-primitivos-mixtos (los valores de lo que sí existe) y cinco de make test-errors; gotcha mixed-primitive-operators.
  • Reinstalar el mismo compilador ya no invalida target/nyx-lib (fricción nyxerp, 2026-10-17). La huella de cada objeto de [lib] llevaba la ruta y el mtime del binario del compilador, y la ruta absoluta de cada std/ del cierre. Como cada make install-local / nyx update arma una carpeta nueva en ~/.nyx/versions/, reinstalar el mismo compilador recompilaba todo: 302 módulos y unos 50 minutos en nyxerp. Ahora el compilador cuenta por el sha256 de su contenido, guardado en target/nyx-lib/.compilador junto a la ruta, el tamaño y el mtime que lo produjeron, y los std/ por su ruta relativa. Caso 9 de run_lib_modules.sh: reinstalación igual reutiliza, otro compilador recompila.
