Pipes

try_spawn_pipeline([argv1, argv2, ...], opts) corre printf … | sort | head -n 2 sin shell. Crea los pipes intermedios y cierra a tiempo los extremos del padre: si el padre se quedara con uno abierto, el siguiente comando de la cadena nunca vería el fin de archivo. opts.stdin alimenta al primer comando y opts.stdout es el del último.

// Pipes — conectar procesos con std/process
// Pipes — connect processes with std/process
//
// `printf 'c\\nb\\na\\n' | sort | head -n 2` sin shell: try_spawn_pipeline crea los pipes
// intermedios y cierra los extremos del padre a tiempo (si no, el EOF nunca
// llega al siguiente de la cadena). opts.stdout es el del ÚLTIMO comando.
//
// Nota: pipe_new + fork + dup2 + execvp (lo que hacía esta receta) siguen
// disponibles en posix; donde no hay fork se usa std/process.
// EN: pipe_new/fork/dup2/execvp remain on posix; std/process is portable.

import "std/process"

fn main() -> int {
    var opts: SpawnOpts = spawn_opts()
    opts.stdout = Stdio.Pipe
    match try_spawn_pipeline([["printf", "c\\nb\\na\\n"], ["sort"], ["head", "-n", "2"]], opts) {
        Result.Ok(hijos) => {
            // collect lee el stdout del último hasta EOF y lo espera.
            let ultimo: Child = hijos[hijos.length() - 1]
            match try_child_collect(ultimo) {
                Result.Ok(r) => {
                    print("exit code: " + int_to_string(r.code))
                    print("lines: " + int_to_string(r.stdout.trim().split("\n").length()))
                }
                Result.Err(e) => { print("collect failed: " + e.msg) }
            }
            // Los demás de la cadena también se esperan (no quedan zombis).
            var i: int = 0
            while i < hijos.length() - 1 {
                let c: Child = hijos[i]
                let _r = try_child_wait(c)
                i = i + 1
            }
        }
        Result.Err(e) => { print("pipeline failed: " + e.msg) }
    }
    return 0
}
Salidastdout
exit code: 0

Cómo funciona

Devuelve los hijos en orden. Con opts.stdout = Stdio.Pipe, try_child_collect sobre el último lee su salida hasta el final y lo espera; a los demás se los espera con try_child_wait para que ninguno quede como zombi. Si un comando no se puede lanzar, los que ya arrancaron se matan y se esperan, y el error dice en e.stage qué paso falló.

Los builtins crudos pipe_new, fork, dup2 y execvp, que usaba antes esta receta, siguen disponibles en posix.
