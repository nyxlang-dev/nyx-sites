Software nativo, documentado para agentes.

Nyx compila a código nativo con LLVM, hospeda su propio compilador y entrega cada proyecto con lo que un agente de IA necesita para escribirlo bien.

Instalación

Linux · x86_64 / aarch64 / armv7l · Termux

01 Instalación

Un comando para instalarlo. Uno para empezar un proyecto.

Requisitosclang, make y git, más las cabeceras de desarrollo de libgc, OpenSSL y zlib. El instalador instala lo que falte con el gestor de paquetes que encuentre: apt, dnf, pacman, apk, xbps, o pkg en Termux.
Instala en~/.nyx, con un enlace en ~/.local/bin/nyx (en Termux, $PREFIX/bin/nyx). Si ese directorio no está en tu PATH, el instalador lo agrega a tu perfil de shell y te avisa.
Verificarnyx --version — imprime la versión instalada.
Actualizarnyx update — trae la versión más reciente, la recompila e imprime qué cambió.
Desinstalarnyx uninstall — borra la toolchain y el enlace que creó.
Primer proyectoterminal
$ nyx init my-app  crea nyx.toml, src/main.nx, AGENTS.md y docs/nyx/$ cd my-app$ nyx run  compila el proyecto y lo ejecuta

Muestra

Cómo se lee el lenguaje.

sample.nxnyx
enum Result { Ok(int), Err(String) }

fn parse_port(text: String) -> Result {
    let n: int = string_to_int(text)
    if n < 1 or n > 65535 { return Result.Err("out of range: ${text}") }
    return Result.Ok(n)
}

fn bind_port(text: String) -> Result {
    let port: int = parse_port(text)?   // ? hands the Err back to the caller
    return Result.Ok(port)
}

fn main() {
    match bind_port("8080") {
        Result.Ok(port) => print("listening on ${port}"),
        Result.Err(why) => print("config error: ${why}")
    }
}
MuestraUn enum con match exhaustivo, propagación de errores con ?, interpolación de strings y tipos explícitos en cada binding.
Verificado connyx check — analiza y chequea tipos, sin linkear y sin ejecutar.
Ejecútalonyx run sample.nx

03 Desarrolla con agentes

Cada proyecto lleva el contexto que un agente necesita para escribirlo.

Lo que siembra nyx init

AGENTS.mdEl manual de campo: cómo se construye un programa acá, los rieles duros y las trampas que arruinan un primer intento. Neutral respecto del proveedor, según la convención agents.md.
CAPABILITIES.mdÍndice generado de la biblioteca estándar — lo que ya existe, para que nadie lo reinvente. Se regenera en cada build.
docs/nyx/La referencia densa más tres guías: escribir un programa, arreglar un error de compilación y reportar fricción.

Herramientas

  • nyx vetNombra las trampas grep-ables en lugar de dejar un error del parser: warning[W101] src/main.nx:12
  • nyx init --agent=claude,cursor,copilotAdaptadores opcionales de tres líneas, uno por herramienta. AGENTS.md sigue siendo la única fuente de verdad; el adaptador solo apunta ahí.
  • nyx init --sddSiembra el andamiaje orientado a especificación: constitución, glosario, plantilla de ADR y specs/ — así el agente pregunta en vez de inventar.
  • nyx reportDeja un FRICTION.md en el proyecto. No se envía nada por su cuenta.
AGENTS.md — sembrado por nyx initextracto
> **REGLA DE ORO — NO leas el fuente del compilador ni de la biblioteca estándar**
> (`std/`, `compiler/`, ni nada bajo tu instalación de Nyx) «para entender cómo funciona».
> No hace falta y te vas a perder. Si buscas una función, búscala en `CAPABILITIES.md`. …

## Rieles duros (NO hagas esto)

- **NO inventes sintaxis.** Si dudas de que una palabra clave o una feature exista,
  probablemente no exista — revisa `CAPABILITIES.md` (o <https://nyxlang.com/by-example/>)
  en vez de adivinar.
- **NO reinventes lo que ya hace la stdlib.** Si `CAPABILITIES.md` lo lista, úsalo.
- **NO parches una limitación.** Repórtala con `nyx report` y detente.
