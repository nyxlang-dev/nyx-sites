La mesa de ayuda de un ERP lee soporte@miempresa.com por IMAP y contesta por SMTP en el mismo hilo (receta 134). Gmail y Microsoft 365 ya no aceptan usuario y contraseña: piden un token OAuth2, y imap_auth_xoauth2 / smtp_auth_xoauth2 lo reciben hecho. Esta receta muestra cómo se OBTIENE y se RENUEVA con std/oauth2.

Tres flujos. La primera vez, una persona autoriza en el navegador: PKCE más state, la URL de autorización y el canje del código. Todas las demás, se renueva antes de que venza y se guarda el refresh_token. Y en un servidor sin navegador, device code: abre esta URL y escribe este código.

Lo que corre aquí sin red es PKCE, el state y la URL de autorización; el verifier, el challenge y el state son aleatorios, así que esos tres valores cambian en cada ejecución. Las funciones que hablan con Google compilan y enlazan pero NO se llaman, porque necesitan un client_id real. Las últimas líneas muestran cómo se lee cada tipo de error: auth trae el motivo del propio proveedor, pending significa que la persona todavía no autorizó y dice cuánto esperar, y protocol que la respuesta no es la de un endpoint OAuth2.
