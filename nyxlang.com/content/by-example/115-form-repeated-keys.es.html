Un grupo de casillas (checkboxes) o un <select multiple> manda el MISMO name más de una vez —ver=a&ver=b&ver=c— pero req.form y req.query son Maps, y un Map no guarda claves duplicadas: parse_form_data/parse_query_string se quedan en silencio con la ÚLTIMA. form_values(req, key) y query_values(req, key) devuelven todos los valores en cambio, en el orden en que llegaron; parse_form_data_all/parse_query_string_all hacen lo mismo sin un Request, como un Array plano de pares [clave, valor].

req.form.get("ver") = c pares totales = 4 form_values(req, "ver") = 3 valores - a - b - c OK: form_values/query_values recuperan TODOS los valores de una clave repetida

req.form.get("ver") muestra la trampa: solo sobrevive "c", la última de las tres casillas — en silencio, sin error. parse_form_data_all(body, content_type) devuelve en cambio los cuatro pares tal como llegaron, listos para filtrar o contar.

form_values(req, "ver") reparsea req.body más el Content-Type de req.headers_flat en cada llamada — no agrega un campo a Request ni cambia lo que ya significa req.form, así que el código existente sigue andando. Una clave ausente devuelve un Array vacío, nunca un error.

query_values(req, key) es la misma idea sobre la query string de req.path, vía parse_query_string_all: ?tag=urgente&tag=bug&q=nyx da dos valores para "tag". Los dos helpers funcionan sobre un Request sintético de request_with(), así que probar un handler no necesita un servidor corriendo.
