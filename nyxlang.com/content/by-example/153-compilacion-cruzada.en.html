To ship one program to both x86_64 and aarch64 machines you do not need to build on each one. nyx build --target x86_64-unknown-linux-gnu (from an aarch64 host) or --target aarch64-unknown-linux-gnu (from x86_64) produces the binary for the other architecture. You can also set [build] target = "..." in nyx.toml. The output goes to target/<triple>/<name> and does not overwrite the native binary.

The program asks uname -m through try_spawn with stdout piped, collects the result with try_child_collect and prints the architecture it is running on; every failure falls back to "desconocida". Build it for each target and check the output on the matching machine (the output above is from an aarch64 host). The host's own triple compiles natively; the other architecture uses clang with --target=<triple> and lld, and the C runtime is compiled for the target and cached per target. On Debian/Ubuntu you need the multiarch packages (libc6-dev, libgc-dev, libssl-dev, zlib1g-dev, libgcc-N-dev for the other architecture, plus lld); if something is missing, nyx build says so before compiling, with the exact command.

Limits: there is no emulation, so the cross-built binary does not run on the machine that built it and nyx run --target <other architecture> fails; copy it to a machine of that architecture or try it in a container with docker run --platform linux/amd64. The binary is dynamic, so the target needs libgc, libssl3, libcrypto, libz and glibc. And asm with x86 one-letter constraints (a b c d S D) is rejected when the target is aarch64.
