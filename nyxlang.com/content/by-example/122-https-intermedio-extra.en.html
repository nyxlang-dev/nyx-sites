It happens more than it should (government sites, banks): the server sends an intermediate certificate that does not match its own, and verification against the system CAs fails with unable to get local issuer certificate (code 20). The right intermediate is public. HttpOpts.cas_extra ADDS it to the system CAs for that one request, so you reach the site without ever disabling verification.

rechazado antes del handshake: invalid 22

The chain and the host name are still verified exactly as before, and the rest of the process — other requests, std/postgres — keeps the trust it had. The value is the PEM CONTENT (one or several certificates), not a path, so it can come from include_bytes or read_file.

The recipe needs no network: a local TCP server accepts the connection, and the program shows that a cas_extra carrying no certificate at all is rejected as invalid (22) BEFORE the handshake, instead of passing silently as it was not needed. A silent pass would be the worst outcome here — you would believe an extra CA was in force when none was.
