Un programa que corre como servicio de Windows

No hay una API nueva para los servicios de Windows. El mismo .exe corre en consola o bajo el administrador de servicios: si lo lanzó el administrador, el runtime lo detecta solo y entrega la parada (sc stop, apagar el equipo) como SIGTERM, igual que Ctrl+Break en consola o kill en Linux. El programa solo tiene que manejar la señal 15 y terminar lo que está haciendo.

// Nyx by Example: un programa que corre como servicio de Windows.
//
// No hay API nueva: el MISMO .exe corre en consola o como servicio. Si lo lanzó
// el administrador de servicios, el runtime lo detecta solo y le entrega la
// parada (`sc stop`, apagar el equipo) como SIGTERM, igual que Ctrl+Break en
// consola o `kill` en Linux. El programa solo tiene que manejar la señal 15 y
// terminar lo que está haciendo.
//
// Instalar (PowerShell como administrador; New-Service y no `sc.exe create`,
// que en PowerShell 5.1 rompe las rutas con espacios):
//
//     New-Service -Name MiTrabajo -StartupType Automatic `
//       -BinaryPathName '"C:\Program Files\MiTrabajo\trabajo.exe" "C:\ProgramData\MiTrabajo\estado.txt"'
//     sc.exe failure MiTrabajo reset= 86400 actions= restart/1000
//     sc.exe start MiTrabajo
//
//   - El directorio de trabajo de un servicio es System32: las rutas van
//     absolutas, por argumento.
//   - Al SCM siempre se le informa salida limpia; `sc failure` actúa solo si el
//     proceso muere sin salir (crash, taskkill /F).

import "std/fs"

var parar: int = 0

fn al_parar(sig: int) -> int {
    parar = 1
    return 0
}

fn main() -> int {
    let args: Array = get_args()
    // Sin argumentos es una demo que termina sola (3 vueltas), para probar la
    // receta sin instalar nada. Como servicio recibe la ruta del estado y corre
    // hasta que lo paren.
    var estado: String = temp_dir() + "/nyx-servicio-demo.txt"
    var max_vueltas: int = 3
    if args.length() > 1 {
        estado = args[1]
        max_vueltas = -1
    }

    signal_handle(15, al_parar)

    var vueltas: int = 0
    while parar == 0 and (max_vueltas < 0 or vueltas < max_vueltas) {
        sleep(100)          // una unidad de trabajo; la señal no la corta a la mitad
        vueltas = vueltas + 1
    }
    write_file(estado, "vueltas=" + int_to_string(vueltas))
    print("listo: " + int_to_string(vueltas) + " vueltas")
    return 0
}
Salidastdout
listo: 3 vueltas

Cómo funciona

signal_handle(15, al_parar) registra un manejador que pone la global parar en 1. El bucle principal hace una unidad de trabajo (aquí un sleep(100)), de modo que la señal no la corta a la mitad, y mira la bandera en cada vuelta. Al salir escribe vueltas=N en el archivo de estado e imprime la cuenta. Sin argumentos es una demo que termina sola tras tres vueltas, para probar la receta sin instalar nada (la salida de arriba); como servicio recibe la ruta del estado por argumento y corre hasta que lo paren.

Para instalarlo, en PowerShell como administrador, se usa New-Service con -BinaryPathName con la ruta del .exe entre comillas y sus argumentos, y después sc.exe failure y sc.exe start (New-Service y no sc.exe create, que en PowerShell 5.1 rompe las rutas con espacios). El directorio de trabajo de un servicio es System32, así que las rutas van absolutas, por argumento. Al administrador siempre se le informa salida limpia; sc failure actúa solo si el proceso muere sin salir (un crash, taskkill /F).
