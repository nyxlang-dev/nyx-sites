A server calls a language-model API that answers with events (text/event-stream) for several seconds. Instead of waiting for the whole answer and showing a spinner, each piece is forwarded to the browser as soon as it arrives. The client half is std/http, which returns with the status and headers and lets the body be read a little at a time; the server half is std/serve, which keeps a Server-Sent Events channel open per request.

The recipe runs on its own: one thread plays the outside API (three delta events and a fin, with pauses), std/serve plays the application, and a plain socket plays the browser. The browser route returns sse_open(req, room) with a room of its own and spawns a thread that calls try_http_stream. On the stream, s.read() gives raw pieces of the body and s.read_event() gives events already assembled (evento, datos, id); each one goes out with sse_broadcast(room, …).

The thread first waits with sse_wait_room(room, 5000): the channel joins the room only after the handler returns, and without that wait the first events would be lost. With try_http_stream_opts the read timeout is the longest wait between two pieces, so a stalled API gives Err(timeout) instead of a hang; there is no total timeout by default. The times in the output depend on the machine, which is why the panel is marked as illustrative.
