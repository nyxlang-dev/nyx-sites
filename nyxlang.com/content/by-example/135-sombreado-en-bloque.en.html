A name redeclared inside a block — if, else, while, for, a match arm, try/catch — is ANOTHER variable. It lives until the block closes and, on the way out, the name goes back to being the outer variable, with its value and its type. Up to 0.35.0 the inner one hid the outer one until the end of the function; from 0.36 on it behaves as described.

ok

The recipe covers three things: shadowing in an if with a DIFFERENT type and with the SAME type; the variable of a for q in ... and the binding of an Option.Some(q) => pattern; and the right way to get a value OUT of a block — declare it outside and assign inside. It prints ok when every outer value came back intact.

One limit to remember: in the same scope there is no block, so let x = x + 1 keeps replacing the previous x, as before.
