0.40.0 2026-10-30

MINOR: new API — std/process (child processes without fork, with the same API on every platform) , std/serial, Error.stage and try_tcp_connect_ms — and Windows W5. Sorting becomes O(n log n), and correctness fixes arrive that nyxerp found in real use: HTTP with lowercase headers, [lib] with cycles, contains after sort_str and /proc.

Migration: (1) Error has a fourth field, stage: an Error { code, kind, msg } literal no longer compiles (NYX1032); use err_new(code, kind, msg), or add stage: "". (2) nyx build --target with a Windows triple now fails with the reason, instead of building a native executable and exiting 0.

Changed

  • sort_int, sort_str and sort_by sort in O(n log n): they were bubble and insertion sort, O(n²); with 32,000 elements sort_by took 15 s and now takes 11 ms. Non-recursive merge sort, stable (equal elements keep their order) and with the same contract: they sort the array in place and return it. Regression +1 (test-517, 534 files).
  • The C runtime is always built with -O2, also without --release, in nyx run, nyx build and nyx test: at -O0 everything living in C ran about 7 times slower (sha256 of 120 MB: 4,858 → 741 ms with nyx run), and nyxerp reported it as PBKDF2 slowness. It is compiled once into the ~/.cache/nyx/rt/ cache (the one build and test already used; nyx run starts using it: before, it recompiled the runtime on every run), with at most as many clang processes at once as there are cores. The user's Nyx code is still not optimized outside --release. Guard in run_toolchain_recipe_audit.sh.
  • pbkdf2_hmac_sha256 about 5 times faster: natively it uses OpenSSL's PKCS5_PBKDF2_HMAC (600,000 iterations: 872 → 166 ms on aarch64 with --release); the in-house implementation, kept for wasm32-wasi, precomputes the SHA-256 states of k^ipad and k^opad once per call (2 compressions per iteration instead of 4; wasm 1,276 → 620 ms). Same result byte for byte (RFC 7914 vectors in test_crypto.c, through both paths). What nyxerp measured (6.2 s) was also the unoptimized runtime outside --release (see the previous item).

Added

  • try_tcp_connect_ms(host, port, ms) in std/net: connect with a deadline of your own: try_tcp_connect waits up to 3000 ms; with a powered-off device on the local network (the store bridge's ticket printers, over TCP 9100) that stalled everyone's status. It returns Err of kind timeout (code 110) if it does not connect in time; ms <= 0 = no deadline of its own. std/http already used it internally and nyxerp declared it as its own extern. Recipe 152; regression +1 (test-520); the expired deadline is still covered in C by test_net_result.c.
  • Error.stage: at which step a multi-step operation failed: Error (std/error) gains the field stage: String, "" when the operation has no stages. err_new does not change and err_stage(code, kind, msg, stage) sets it. std/process fills it with exec, stdin, stdout, stderr or cwd: a redirection that fails to open and a nonexistent program both give not_found, and nyx-shell told them apart by searching for text in msg. A hand-written Error { code, kind, msg } literal now needs stage (there was none outside the std). test-518 covers each stage.
  • std/serial: native serial port for server programs: try_serial_open(path, baud, data_bits, parity, stop_bits), try_serial_write, try_serial_read(p, max, deadline_ms) (Ok("") = the deadline expired with no data), try_serial_read_until(p, end, max, deadline_ms) for STX…ETX frames (it does not consume the byte after the end, e.g. the LRC), try_serial_close and serial_ports() with USB VID:PID. Linux (termios, /sys/class/tty) and Windows (\\.\COMn, DCB, SetupAPI; not yet verified on real Windows); macOS opens and lists without VID/PID. Exclusive open (in_use), DTR active, raw mode without flow control, standard speeds only. Bytes as String, with adapters for the Array of std/browser_serial. Through extern "C", without touching the compiler. Requested for nyxerp's store bridge (fiscal printer and scales).
  • std/process: launch child processes without fork: try_spawn(argv, SpawnOpts) with each stream as Stdio (inherited, null, pipe or file), cwd and env; try_spawn_pipeline for a | b | c; wait/try_wait, kill, signal (posix only), read/read_err/write/close_stdin and collect, which drains stdout and stderr at the same time (reading them one after the other hangs on large output). posix on top of posix_spawnp; Windows on top of CreateProcessW with the command line built from argv (written, not yet verified on real Windows). Errors not_found, permission and invalid with the stage in the message; writing to a child that closed its stdin gives EPIPE, it does not kill via SIGPIPE. Regression +1 (test-518); C runtime +2 suites (test_os_proc_spawn.c, test_os_win_cmdline.c).
  • Recipes 64 and 65 with std/process, new recipe 151 and the win32 error that points to it : 64 (launch a program) and 65 (pipes) move from fork/execvp/pipe_new to try_spawn and try_spawn_pipeline, with a note that the raw builtins remain posix; 151 captures stdout and stderr with try_child_collect. Under win32, fork, execvp, waitpid, pipe_new and kill_process are still forbidden, but the message now says "use std/process". By-example recipes 151 (make test-examples: 158 with the 7 at the root). Documented in LLM.md (blocking, nonexistent program = not_found at launch, .bat/.cmd rejected on Windows, signal posix only) and in docs/SPEC.md.
  • TLS on Windows: a root the system has not downloaded yet no longer breaks the connection: Windows ships few roots installed and downloads the rest when building a chain, so an arbitrary site failed with X509 20 on a new machine. On that error, with the system store, the chain is requested from CertGetCertificateChain, the store is reloaded and it retries once; verification is still OpenSSL's. No changes on posix or wasm (written, not yet verified on real Windows).
  • W5: processes, signals and dl adapters compile for Windows: exec, exec_code, getpid, getcwd, chdir, stat, isatty, open_fd, close_fd, dup2, fsync, fdatasync, signal_* and setup_shutdown_handler leave the win32 gate. On Windows, exec() normalizes \r\n to \n and exec_code() gives 127 for a nonexistent command when the line is simple. SIGINT and SIGTERM arrive through SetConsoleCtrlHandler: Ctrl+C gives SIGINT, and Ctrl+Break, console close, logoff and shutdown give SIGTERM, with up to 4.5 s for the closure (the persist flush) to finish. taskkill /F and TerminateProcess give no notice. The sqlite, zlib and llama adapters also try the .dll names, and compress.c loads zlib entirely through dl (no <zlib.h> and no mandatory link). fork, execvp, waitpid, kill_process and pipe_new stay posix-only, until the procesos-spawn arc. No changes on Linux. Verified on Windows 11 x64 (laptop): processes, dl, real Ctrl+C and the persist drain; std/serial only on no-port errors (no hardware).

Fixed

  • try_read_file and read_file read /proc files: the runtime sized the buffer with the file size, and /proc reports 0; /proc/self/status gave Ok("") with no error (cat: 1,184 bytes). Now it reads until EOF and uses the size only as a hint for the first buffer; a stream with no position (FIFO) still gives ESPIPE. C runtime +7 asserts (test_file_result.c).
  • contains and indexOf find texts again after sort_str: merge sort moved elements with dst[i] = src[j], and that slot-to-slot copy left the tag at 0 (unknown); contains and indexOf only compare by content in slots tagged as String, so they returned false and -1 on an array that did have the text, with no error. Codegen now propagates the source tag in an indexed assignment whose value comes from another slot, and the insertion swap uses a temporary slot. The case of an untyped intermediate variable (let t = a[i]; b[k] = t) stays filed in TASKS.md. Regression +1 (test-521-sort-conserva-tags, also sort_by and sort_int); codegen_call_expr grows 16 B in the stack guard.
  • Docs: sort_int, sort_str and sort_by sort the array they receive: LLM.md did not document them and nothing warned that they sort in place and return the same array; let sorted = sort_str(keys) broke nyxerp's pairing of keys with values, with no error. New entry in LLM.md §Array and the sort-in-place trap (AGENTS.md in both languages), with the way to sort a copy: sort_str(xs.slice(0, xs.length())). AI-first +1 (44-sort-ordena-en-el-lugar); build_manifest +1 (the Windows case from the next entry).
  • nyx build --target x86_64-pc-windows-msvc no longer builds native silently: the Windows triples passed validation (codegen knows them), but nyx build does not link for Windows: it printed "build complete", exited 0 and left an executable for the current platform. Now it fails with the reason, like an unknown triple, and the nyx help no longer advertises "Windows (cross)". New case in run_build_manifest.sh.
  • HTTP: a request body is no longer lost if the header arrives as content-length: the C parser (the one in http_serve and std/serve) required ": " as the separator and compared Content-Length with exact capitalization, so content-length: 5 or Content-Length:5 reached the handler with an EMPTY body and no error. Now header names are case-insensitive and the : allows optional spaces on both sides of the value (RFC 9110 §5.1 and §5.6.3), also in the Nyx parsers of std/http (requests, responses by fd and over TLS) and in the upstream response of std/proxy. Each header's value arrives without those spaces. Regression +1 (test-519, both parsers); test_net.c +15 asserts.
  • [lib] modules: two libraries that import each other now compile: a's unit was not counted as imported, so when coming back through b's import another copy of a was inlined and its structs appeared twice in the IR ("redefinition of type" in clang). Uncovered by run_lib_real on nyxerp's formatos ↔ formatos_lienzo. New case in run_lib_modules.sh.
  • win32: try_exec_full no longer hangs without a console: from a service the child read from a new console and never returned; now it gets stdin NUL and is created with CREATE_NO_WINDOW.
  • win32: an invalid fd gives EBADF, not __fastfail: CRT invalid-parameter handler; and isatty gives 0 for NUL (confirmed with GetConsoleMode).
  • win32: tls.c compiles with the MSVC CRT and its e.code is canonical: static OpenSSL from vcpkg in the gate (job w5-tls); persist.c and compress.c enter the subset, and <gc.h> in the four .c files that still used <gc/gc.h>.
  • sqlite: a missing symbol is "library absent", not a crash: before, the library loaded with a null pointer that blew up on the first call. Now try_sqlite_open returns the cause with the symbol and library name, and sqlite_open reports it once on stderr. New variable NYX_SQLITE_SO, which pins the library.
  • The parser no longer silently cuts off programs of more than 100000 statements: the main loop had a fixed limit; on exceeding it, it printed "too many iterations" and went on with the program half parsed. A project with many imports lost its whole main.nx: nyx check exited 0 and the build failed with "undefined reference to main". Now the bound is the number of tokens, and exceeding it is a hard internal error. parser-sin-tope guard in make test-ai-first.
  • A chain of more than 50 postfix operations now compiles: a.b().c()… had a 50-round limit in the parser, and operation number 51 gave NYX0107 on valid code. Now the loop ends when a round consumes no token. Regression +1 (test-515, 532 files).
  • An Fn variable or parameter shadows the global fn of the same name in the result TYPE too : the call already went to the closure, but let r = f(41), match f(41) and f(41)? took the return type of the global fn f (even if it was in another module). nyx check passed and the build failed far from the cause (NYX2007 on a field, or invalid IR). With a lambda in the same function, a local closure returning a struct by value gave invalid IR even without a same-named global. Regression +1 (test-516, 533 files).

0.39.0 2026-10-27

MINOR: new API — std/crypto (AES-GCM), std/exec (try_exec_full), try_ping, the local-network UDP primitives and std/mdns (codec) — and two behavior changes: task_cancel becomes cooperative and NYX1047 rejects code that used to compile.

Migration: (1) task_cancel(t) NO LONGER stops the task: a task running a loop has to check task_cancelled() and return (a sleep inside it returns on its own when cancelled). A task that neither checks nor sleeps keeps running. (2) NYX1047 ships straight as an error, without the prior warning that rule 7 of docs/VERSIONING.md asks for (exception approved by Ottavio): what it rejects —for x: dyn T in arr or let y: dyn T = arr[0] over an Array of concrete structs— died with SIGSEGV as soon as it ran, and a search of the consumers found zero cases. The way out is declaring the Array as Array<dyn T>.

Added

  • std/crypto: authenticated AES-GCM encryption, both directions: to store secrets that must be reused in clear (each customer's SMTP password) without leaving them readable in the database. try_aes256gcm_seal/try_aes256gcm_open pick a random nonce (nonce ‖ ciphertext ‖ tag); try_aes256gcm_encrypt/decrypt and try_aes128gcm_* take an explicit nonce (try_aes128gcm_decrypt opens what Web Push's aes128gcm_encrypt produces, which had no inverse). A bad tag = Err(invalid 74) without releasing the text. GCM specification vectors in test-stdlib-14-aes-gcm; recipe 147.
  • csprng_bytes on wasm32-wasi (via getentropy/random_get): it did not exist before, and every program importing std/webpushcrypto or std/oauth2 failed to link on wasm. The browser shim no longer falls back to Math.random without crypto.getRandomValues: it returns NOSYS and csprng_bytes gives "".
  • std/exec: try_exec_full(cmd) -> Result<ExecResult, Error> — stdout, stderr and exit code separately (ExecResult { stdout, stderr, code }); before, exec gave only stdout and exec_code only the code (anonymous request of 2026-07-23, archived without a task). Reads both streams at once (poll on posix, one thread per stream on Windows), so it does not hang when one fills its pipe; binary-safe, no \n stripping; code = 128+signal if a signal killed it, 127 if the command does not exist; Err only if it could not launch (and 95 on wasm). New os_proc_run_full layer (win32 written, not compiled). test-512, 3 cases in test_os_proc.c, recipe 148.
  • Local network, first batch: std/net gains try_udp_recvfrom_from / try_udp_recvfrom_from_timed (the datagram with the sender's IP and port; ms deadline via poll), try_udp_bind_shared (shared port; try_udp_bind is unchanged), try_udp_join/leave, try_udp_set_multicast_ttl/loop/iface and try_udp_set_broadcast, on new os-layer primitives (win32 written, not compiled). And std/mdns, the base of the module: a pure codec for mDNS messages (RFC 6762/6763) with A/PTR/SRV/TXT records and defensive name decompression (backward pointers only, caps on jumps, label, name and records) that returns Err("parse") instead of aborting; verified against dnslib and python-zeroconf packets and over 1000 mutations. The probe measured that a network read with a deadline inside spawn {} holds a scheduler worker: the reader goes in thread_spawn (HIGH task for the I/O primitive). Tests test-stdlib-15-net-multicast (SKIP if the environment does not deliver multicast) and -16-mdns-codec.
  • std/net: try_ping(host, timeout_ms) -> Result<PingReply, Error> (ICMP echo IPv4, { ip, rtt_us }): an unprivileged datagram ICMP socket where the system allows it (Linux with an open ping_group_range, macOS), raw as a fallback; IcmpSendEcho on Windows (written, not compiled). Anonymous request of 2026-08-05, archived without a task. test-stdlib-17-ping (SKIP if the system forbids ICMP), recipe 149.
  • TLS and the HTTP client on Windows, first part (Ottavio's decision: static OpenSSL + the Windows certificate store's CAs): os_sys_root_certs reads the «ROOT» store and tls.c adds those CAs to OpenSSL; tls_*, https_* and http_get/post/request leave the win32 gate. Written, not compiled: linking vcpkg's OpenSSL and verifying it are W5 Task 4, on the laptop. Nothing changes on Linux.
  • CHANGELOG.en.md, the English CHANGELOG from 0.33.0 (Ottavio's decision): published at nyxlang.com/changelog/. Each release translates its entry: release-check.sh refuses to cut without it and the new check 13 of make docs-health requires the same headings, subsections and items per version.

Changed

  • task_cancel is cooperative (Ottavio's decision; W5 spike §5): it requests cancellation and the task checks it with the new builtin task_cancelled() -> bool (Go's ctx.Done()); sleep() inside a cancelled task returns at once. Before, it was pthread_cancel on Linux (a task that only allocates kept running forever; 200 of them brought WSL down) and TerminateThread on Windows (it could leave the GC lock held and hang the process, 4 out of 5); both skipped defer. Behavior change: a task that neither checks nor sleeps is no longer stopped. test-513 with the spike's scenarios.

Fixed

  • NYX1047: for x: dyn Trait in arr and let y: dyn Trait = arr[0] over an Array of concrete structs passed nyx check and died with SIGSEGV (anonymous report of 2026-09-08, archived without a task): turning into dyn changes the representation when the element is WRITTEN, and reading a struct as a fat pointer crashes. It is now an error asking for Array<dyn Trait>; an untyped Array full of already-dyn values keeps working (test-391). Residue: an Array that arrives filled from another function is not detected. 3 cases in test-errors.
  • win32: runtime/csv.c joins the subset (test-141 had not linked since e0a02263; the laptop's patch). TerminateThread left os_thread_cancel (it could hang the GC, 4 out of 5) and was superseded the same day by cooperative cancellation (see «Changed»).
  • x86_64 on WSL2 (W5 spike): nyx_ev_pipe_write_fd (test-161 assumed pipe() gives consecutive fds and WSL inherits an fd 5), the «connection refused» tests are skipped with a notice when loopback does not refuse (mirrored mode), and run_stack_frame_audit.sh has per-architecture ceilings.
  • std/smtp with a «Name <address>» sender or recipients: the envelope went out as MAIL FROM:<Shop <sales@x.com>> (a real server rejects it), the Message-ID took x.com> as its domain and an accented name traveled as raw UTF-8 in From. Now MAIL FROM and RCPT TO carry only the address, the Message-ID uses its domain and the display name of From/To goes out in RFC 2047 when it is not ASCII (without the quotes around it). New test test-stdlib-13-smtp-remitente-nombre.
  • The std/postgres pool cleans the session and replaces dead connections: pg_pool_put only did ROLLBACK, so a SET, a temp table or a LISTEN leaked to the next request, and a connection cut by the server went back to the pool and was handed out broken again and again. It now does ROLLBACK + DISCARD ALL and, if that fails, closes the connection and empties the slot (the next get reconnects). New pg_pool_discard. Points 3 and 4 of the 2026-09-27 request. tests/postgres/10-pool-sanea.nx.
  • wcwidth gives 2 for wide emoji (U+270A, U+231A...): __ucs_wide is now exactly Unicode 15's East Asian Width W/F. html_unescape knows the 253 HTML 4.01 entities (before, ~50) and &#0; gives U+FFFD instead of a 0 byte. Anonymous requests of 2026-07-31, archived without a task. New cases in test-302/test-303.

0.38.0 2026-10-26

MINOR: new API for processing tabular data: the columnar reader try_csv_read in std/csv and string_to_X_range. In addition, an integer that does not fit in 64 bits is now invalid instead of saturating: string_to_int on such a number now aborts (before, it silently gave INT64_MAX).

Migration: if your code checks that the text is only digits and then calls string_to_int, a number of 19+ digits that arrives from outside now aborts the process (before, it saturated). The way out is string_to_int_or(s, def) or rejecting the overflow beforehand. Today this affects nyx-kv (INCRBY, LRANGE, SCAN, SET … EX, INCR), nyx-db (LIMIT/OFFSET), nyx-proxy (max-age) and the kv webhook: do not recompile them with 0.38.0 until they have their fix (filed in TASKS.md).

Added

  • string_to_int_range(s, ini, fin, def) / string_to_float_range(s, ini, fin, def): parse the number in bytes [ini, fin) of s without creating the substring; they always yield the same value as string_to_X_or(s.substring(ini, fin), def). Reason: in a 5M-row CSV, split() + string_to_float per row makes ~11 GC allocations per row and takes half the time (bench 2026-10-25 against Python/pandas/polars). Pre-sizing the split() Array was tried earlier and discarded: −4% on the giant split, +4..9% on the short ones. +1 test (507), recipe examples/by-example/145-csv-sin-split.nx.
  • std/csv: columnar reader try_csv_read(texto, esquema, opts): parses in a single pass straight into typed columns (int, float, str, and cat = codes + dictionary), with the core in the new runtime/csv.c (RFC 4180: quotes, line breaks inside quotes, CRLF, BOM). Strict: an invalid value is an Err with row and column. try_csv_guess_schema proposes the schema. In the 5M-row bench, grouping and filtering takes 0.93 s and 265 MB, against 1.21 s for pandas and 1.19 s for polars with one thread (with split() + Map: 5.5 s). +1 test (509), +1 C suite (test_csv.c), recipe 146-csv-columnar.

Changed

  • An integer that does not fit in 64 bits is invalid, not saturated: string_to_int aborts with its own message, string_to_int_or/_range return the default, and an int column of try_csv_read gives Err (“does not fit in an int” («no entra en un int»)). Before, strtoll left it at INT64_MAX/MIN and nobody checked ERANGE: string_to_int_or("99999999999999999999", 0) silently gave 9223372036854775807 (Ottavio's decision). Consequences that were fixed along with the change: std/json stores such an integer as "float" with its text (before, it saturated it; with the change it would have aborted the process on a number coming from outside), and the interpreter/REPL applies the same NYX2015 rule as the compiler: -9223372036854775808 gives exact INT_MIN (it gave -9223372036854775807) and a literal that does not fit is an error (it gave INT_MAX). +2 tests (510, 511), +1 C suite (test_int_parse.c), +2 checks in the REPL smoke test.
  • string_to_float / _or / _range parse with the Clinger fast path: a number [+-]digits[.digits] of up to 15 digits is converted with one exact division, which gives the same double as strtod bit for bit; the rest (exponents, 16+ digits, inf, hex, whitespace) still goes to strtod. Verified against strtod on 5M random values and on the edge cases (test_float_parse.c). In the bench of 5M rows, indexOf + _range drops from 2.67 s to 2.13 s. +1 test (508), +1 C suite.

0.37.0 2026-10-22

MINOR: two warnings from 0.36.x become errors, as announced (rule 7 of docs/VERSIONING.md): NYX1010 between integer and String, and NYX1045 on an unknown escape. Everything else is additive: std/pdf_render, chunked HTTP responses, wildcard SNI, http_serve_en, DNS records, nyx build -j N and several improvements to std/pdf, std/xlsx, std/image and std/smtp. Before the cut, 1201 files were reviewed (nyxerp, the products, the sites, and std, examples and compiler of this repo) with the 0.36.x compiler: not a single case of the two warnings.

Changed

  • NYX1010 between integer and String is an error (a warning in 0.36.x). 5 + "a", 5 == "5" and "a" < 5 compiled and died with SIGSEGV when the line ran; now they do not compile, with the same hint (int_to_string, string_to_int_or). The three test-nyx1010-*-mixto cases move to the error list of run_error_tests.sh. It is still a warning when one side reads a slot (dst[1] == "dos"): the inferred element type of an Array can lie (var dst = [9] and then dst.push(src[1]) with a String) and the slot carries its tag, so that program works (test-323, case 6; warning in test-nyx1010-casilla-aviso).
  • NYX1045 on an unknown escape is an error (a warning in 0.36.x). "\q" or "\e" were worth the letter without the backslash; now the analysis rejects them with the line and the list of valid escapes (\x1b instead of \e). It comes out with the format and NDJSON of the other analysis errors ("severity":"error").

Added

  • std/http: http_serve_en(host, port, handler) and http_serve_mt_en(host, port, workers, handler) choose the bind address; http_serve/http_serve_mt stay on 0.0.0.0 for compatibility (gotcha http-serve-all-interfaces). The playground moves to 127.0.0.1:8081: in production it was left open directly even though the gateway serves it (server order, 2026-10-21). Test test-505-http-serve-en (binds 127.0.0.2 and checks that 127.0.0.1 does not connect).
  • Wildcard SNI in the TLS server: tls_server_add_cert("*.dominio", cert, key) covers one label (a.dominio, not dominio nor a.b.dominio, RFC 6125), exact names win over the wildcard regardless of order, the comparison is no longer case-sensitive and the cap goes up from 16 to 64 domains. Request from nyxerp (phase C0 of its automatic onboarding of customers <cliente>.nyxerp.com). Test test_sni_name_matches (runtime) and real handshake verified with openssl s_client.
  • std/http: reading a response in chunks (nyxerp friction 20261019-200016-team-1: forwarding to the browser each chunk of a language-model API as soon as it arrives). try_http_stream_opts(method, url, headers, body, http_stream_opts()) → HttpStream, which returns with the status and the headers:
    • read() gives body chunks without the chunked framing; read_event() gives text/event-stream events already assembled (SseEvent { evento, datos, id }, WHATWG).
    • Deadlines connect_ms, primer_byte_ms, lectura_ms (between two chunks) and total_ms (no cap by default). HTTP and HTTPS.
    • sse_wait_room(room, ms) in std/serve closes the forwarding race: the channel enters the room after the handler returns, and without waiting the first events were lost.

Silently-wrong: the drop went by name and by function, so in a loop each iteration overwrote the same slot and only the last value was released (the rest was lost without a warning); a throw released nothing; and two homonymous affines were NYX2020. The flag of a returned value is turned off before the exits. The function's cleanup section, %__defer_retval and NYX2020 are gone. Test tests/ai-first/38; gotcha drop-per-declaration.
  • A defer runs only if it was reached, and a throw runs the reached defers . Silently-wrong: if b { return 1 } defer {...} ran the defer with b true, because the cleanup section generated all the top-level ones on every exit. And a throw skipped all the cleanup. Now the function body is one more scope (the defers are generated inline at the exits that reached them) and each defer, when executed, pushes an implicit try frame whose catch runs it and rethrows: the reached ones run, innermost to outermost, before the catch; a throw inside a defer does not repeat it.   • A method on a primitive const (K.to_string(), local or imported) gave "NYX2002: method 'to_string' is not available on the global 'K'": an int/float/bool const is inlined and is not a variable, so it fell into the globals branch. Now it is materialized as a local variable and follows the normal path; the Map trio (contains/insert/get) still gives NYX2007 on a const. Regression: test-453. Along the way it was filed that the same trio on an int VARIABLE gives invalid IR with no diagnostic (a previous bug). The generic "method not available on this receiver" error (the catch-all of codegen_method_call) carried no code: it is now NYX2002, like the one for globals — a nonexistent method on a const still gives NYX2002.
  • Internal: interfaz_de (the per-interface fingerprint of [lib], compiler/build.nx) compares against char literals instead of ASCII codes, now that the bug that forced it is fixed.
  • Toolchain: a new version no longer inherits the active one's .fijada mark. install-local builds the new version by copying the active one, and if that one was pinned (today, nyxerp's production one) the copy carried the mark along: the new version ended up pinned without anyone asking, and pruning would never delete it. nyx_tc_publicar removes the mark before publishing. Guard: run_toolchain_versions.sh (4b), red without the fix.
  • An opaque value can be passed directly to any builtin. An element of an untyped Array (get_args()[i], an Array returned by a fn), m.get(k) or the return of a signature-less Fn reached the builtins as i64, and nobody converted it: read_file(args[2]) went down to call @nyx_read_file(i8* %<i64>) —invalid IR that clang rejected at link time, with nyx check green—. Measured: 76 of 87 builtins with a pointer parameter (files, environment, crypto, regex, network/TLS, mutex/channels/condvar/rwlock, panic, …). A single helper (codegen_arg and its four forms, in compiler/codegen.nx) converts the argument to the type that the handler already declares: inttoptr towards a pointer, ptrtoint towards an i64 slot (so channel_send(ch, <String>), which did not link either, works). The four forms do not carry the type as a literal so as not to bloat the frame of codegen_call_expr (measured: +5.4 KB per level with the literal; with the forms, within the ceiling). New guard: run_builtin_arg_opaco.sh (in test-ai-first; 76/87 red with the previous compiler), and test-451 checks the result, not just the IR (sha256, setenv/getenv, write/read_file, a String through a channel, a mutex taken out of an Array). Closes two TASKS entries.
  • std/postgres: the pool is thread-safe (friction from nyxerp, 2026-09-27). With std/serve and 16 threads sharing one pg_pool_new, the server hung in 3 of 6 runs; with 8, it died with "Index 0 out of range" (original: «Índice 0 fuera de rango»). try_pg_pool_get looked for a free slot and marked it in use in two steps without a lock: two threads took the SAME connection and mixed the protocol on one socket. PgPool now carries a mutex (field mu) taken only for the slot state, never during I/O (connecting, the ROLLBACK of pg_pool_put, closing). Regression: tests/postgres/09-pool-hilos.nx (16 threads × 300 queries over a pool of 4, each response checked against its thread): with the previous pool it fails 4 of 4 runs, with the new one it passes 9 of 9.
  • std/serve: an idle connection that times out with a request already arrived is served, not reset. The parking sweep (runtime/net.c) closed on timeout without checking whether the socket already had a request that the event loop had not yet seen; closing with unread data makes the kernel send an RST, and the client saw ECONNRESET on a request that the server did receive. Now the expired ones with data are handed to the workers. It came out of analyzing nyxerp's load test (ECONNRESET only under saturation); the data point mostly to the keep-alive race of the generator itself, so this is a hardening, not the measured cause. Deterministic regression with a -DNYX_RUNTIME_TESTING hook (parking thread held still): test_http_park_vencida_con_pedido, red without the fix (the client receives ECONNRESET).
  • Assigning an opaque value to an already declared variable converts it to its type (nyxerp friction 20260925-090024). let x: S = xs[0] worked, but var s: S = … + s = xs[0] emitted store %S %<i64>: invalid IR, nyx check silent and the link rejected by clang. The conversion of the opaque value (xs[i], m.get(k), return of a signature-less Fn) lived inline in codegen_let and assignment had a partial copy (only String and Array); now both use coerce_opaque_i64 — struct, enum, Map, bool, char, narrow integers, float, Array<T>, Fn(...) — and n = m.get(k) on a declared int does the ptrtoint. Regression: test-450-asignar-valor-opaco-a-var-declarada (9 type families).
  • std/serve: HEAD no longer contaminates the keep-alive connection. A HEAD fell to the 404 and the 404 went out with a body; a proxy that reused the connection (nyx-gateway) read those bytes as the start of the next response and returned a 502 to another user — seen in production at serve.nyxlang.com on 2026-09-25. Now a HEAD without its own route uses the GET route of the same path (also in mounted routers; an explicit HEAD route wins) and every response to a HEAD goes out without a body with the GET's Content-Length (RFC 9110 §9.3.2); an sse_open does not open the channel on a HEAD. Regression: 8 new checks in test_serve_std_keepalive.py (HEAD + GET pipelined on the same connection; 13 → 21).
