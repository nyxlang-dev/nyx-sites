The tablets of a shop have the application installed (a PWA) and talk to a server on the same network, so they keep working when the internet goes down. This is a browser recipe for wasm32-wasi: it is built with nyx build --target wasm32-wasi and uses the DOM, so it cannot run natively and the output above is illustrative.

Chrome asks for the Local Network Access permission (formerly Private Network Access) before a page may talk to a machine on the LAN. It is requested with targetAddressSpace on fetch — the third argument "local" of these functions; "" means do not ask, and a browser that does not know the field ignores it, so it never breaks the request. The server has to cooperate too: CORS and, if the browser sends a local-network preflight, an answer to it. That part could not be verified against a real Chrome from the repository; the tests pin that the shim passes the field and that the timeout aborts the request.

Against a machine that is off, a fetch waits for minutes. The timeout (in ms, 3000 here) aborts it and returns an Err with kind "timeout", or "connection" if there was no response at all, which enviar_pedido turns into a message instead of leaving the tablet hanging. On SSE the timeout is for CONNECTING, not for the life of the channel: if it expires, or the connection fails, the handler receives the "nyx-error" event ONCE with data "timeout" or "connection", and the channel closes by itself. Because the program waits on the host, nyx build needs binaryen (or NYX_WASM_OPT).
