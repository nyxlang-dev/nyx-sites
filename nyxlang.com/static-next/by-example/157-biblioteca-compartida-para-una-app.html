A shared library (.so) for an app

A Nyx program can be built as lib<name>.so instead of an executable, so something else loads it: an Android app through JNI, a C program with dlopen, Python with ctypes. Run nyx build --shared (output target/lib<name>.so), add --target aarch64-linux-android for Android, or set [build] kind = "shared" in nyx.toml.

// Nyx by Example: una biblioteca compartida (.so) para una app.
//
// Un programa Nyx puede armarse como `lib<nombre>.so` en vez de un ejecutable, para que
// otra cosa lo cargue: una app Android por JNI, un programa en C con dlopen, Python con ctypes.
//
//   nyx build --shared                                  -> target/lib<nombre>.so
//   nyx build --target aarch64-linux-android --shared   -> target/aarch64-linux-android/lib<nombre>.so
//   # o fijarlo en nyx.toml:  [build]  kind = "shared"
//
// Reglas del modo --shared:
//   1. Solo las funciones con #[export_name("x")] salen de la .so, con ese nombre C. Todo lo
//      demás queda oculto (también los `pub`).
//   2. Su firma usa solo int (int64_t), float (double), bool, punteros crudos y String.
//      Un String ENTRA como (const uint8_t *ptr, int64_t len) —bytes UTF-8, puede traer NUL— y
//      SALE como `nyx_buf *` (malloc fuera del GC); quien llama lo libera con nyx_buf_free.
//      Cualquier otro tipo es NYX1048.
//   3. `fn init()` es opcional y corre UNA vez, al cargar la biblioteca (nyx_lib_init).
//   4. Una .so no tiene `fn main` (NYX1049): nadie la llamaría. El `main` de abajo existe solo
//      para que esta receta se pueda ejecutar como programa normal; en --shared se BORRA.
//   5. Un assert o un panic dentro de la .so mata la app entera (ver
//      docs/gotchas/shared-lib-fatal-mata-app.md). Los errores esperables salen como códigos.
//
// El estado de larga vida (una conexión, un servidor) se guarda del lado de Nyx y se entrega
// al llamador como un `int` opaco que él devuelve en cada llamada.

var g_llamadas: int = 0

// Corre una vez al cargar la .so (en este programa normal, la llama main).
fn init() {
    g_llamadas = 0
}

#[export_name("app_echo")]
fn echo(s: String) -> String {
    g_llamadas = g_llamadas + 1
    return s
}

#[export_name("app_llamadas")]
fn llamadas() -> int {
    return g_llamadas
}

// Solo para el runner de las recetas: en `nyx build --shared` este main no va.
fn main() {
    init()
    let r: String = echo("hola, app")
    assert(r == "hola, app")
    assert(llamadas() == 1)
    print(r)
}
Outputstdout
hola, app

How it works

Here echo is exported with #[export_name("app_echo")] and llamadas as app_llamadas; init resets a global counter. Run as a normal program, main calls init, calls echo("hola, app"), asserts the result and the counter, and prints hola, app. That main exists only so the recipe can run: in --shared mode it is removed, because a .so with fn main is error NYX1049.

The rules of the mode: only functions with #[export_name] leave the .so, under that C name; everything else stays hidden, pub included. Their signature may use only int (int64_t), float (double), bool, raw pointers and String; any other type is NYX1048. A String comes in as (const uint8_t *ptr, int64_t len), UTF-8 bytes that may contain NUL, and goes out as a nyx_buf * allocated with malloc outside the GC, which the caller frees with nyx_buf_free. An optional fn init() runs once, when the library loads. Keep long-lived state (a connection, a server) on the Nyx side and hand the caller an opaque int to pass back on every call.

Important limits: a failed assert, a panic, running out of memory or an NYX2022 inside the .so kills the whole host app, with no recovery; return expected errors as codes or buffers. Load only one Nyx .so per process, since each brings its own GC and runtime, and never call an exported function from the UI thread, because it runs on the caller's thread and blocks it; use a thread of your own. The templates/android directory of the language repo has the JNI shim and a Kotlin bridge to copy into a Gradle project.
