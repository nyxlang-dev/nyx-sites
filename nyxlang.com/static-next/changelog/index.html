0.39.0 2026-10-27

MINOR: new API — std/crypto (AES-GCM), std/exec (try_exec_full), try_ping, the local-network UDP primitives and std/mdns (codec) — and two behavior changes: task_cancel becomes cooperative and NYX1047 rejects code that used to compile.

Migration: (1) task_cancel(t) NO LONGER stops the task: a task running a loop has to check task_cancelled() and return (a sleep inside it returns on its own when cancelled). A task that neither checks nor sleeps keeps running. (2) NYX1047 ships straight as an error, without the prior warning that rule 7 of docs/VERSIONING.md asks for (exception approved by Ottavio): what it rejects —for x: dyn T in arr or let y: dyn T = arr[0] over an Array of concrete structs— died with SIGSEGV as soon as it ran, and a search of the consumers found zero cases. The way out is declaring the Array as Array<dyn T>.

Added

  • std/crypto: authenticated AES-GCM encryption, both directions: to store secrets that must be reused in clear (each customer's SMTP password) without leaving them readable in the database. try_aes256gcm_seal/try_aes256gcm_open pick a random nonce (nonce ‖ ciphertext ‖ tag); try_aes256gcm_encrypt/decrypt and try_aes128gcm_* take an explicit nonce (try_aes128gcm_decrypt opens what Web Push's aes128gcm_encrypt produces, which had no inverse). A bad tag = Err(invalid 74) without releasing the text. GCM specification vectors in test-stdlib-14-aes-gcm; recipe 147.
  • csprng_bytes on wasm32-wasi (via getentropy/random_get): it did not exist before, and every program importing std/webpushcrypto or std/oauth2 failed to link on wasm. The browser shim no longer falls back to Math.random without crypto.getRandomValues: it returns NOSYS and csprng_bytes gives "".
  • std/exec: try_exec_full(cmd) -> Result<ExecResult, Error> — stdout, stderr and exit code separately (ExecResult { stdout, stderr, code }); before, exec gave only stdout and exec_code only the code (anonymous request of 2026-07-23, archived without a task). Reads both streams at once (poll on posix, one thread per stream on Windows), so it does not hang when one fills its pipe; binary-safe, no \n stripping; code = 128+signal if a signal killed it, 127 if the command does not exist; Err only if it could not launch (and 95 on wasm). New os_proc_run_full layer (win32 written, not compiled). test-512, 3 cases in test_os_proc.c, recipe 148.
  • Local network, first batch: std/net gains try_udp_recvfrom_from / try_udp_recvfrom_from_timed (the datagram with the sender's IP and port; ms deadline via poll), try_udp_bind_shared (shared port; try_udp_bind is unchanged), try_udp_join/leave, try_udp_set_multicast_ttl/loop/iface and try_udp_set_broadcast, on new os-layer primitives (win32 written, not compiled). And std/mdns, the base of the module: a pure codec for mDNS messages (RFC 6762/6763) with A/PTR/SRV/TXT records and defensive name decompression (backward pointers only, caps on jumps, label, name and records) that returns Err("parse") instead of aborting; verified against dnslib and python-zeroconf packets and over 1000 mutations. The probe measured that a network read with a deadline inside spawn {} holds a scheduler worker: the reader goes in thread_spawn (HIGH task for the I/O primitive). Tests test-stdlib-15-net-multicast (SKIP if the environment does not deliver multicast) and -16-mdns-codec.
  • std/net: try_ping(host, timeout_ms) -> Result<PingReply, Error> (ICMP echo IPv4, { ip, rtt_us }): an unprivileged datagram ICMP socket where the system allows it (Linux with an open ping_group_range, macOS), raw as a fallback; IcmpSendEcho on Windows (written, not compiled). Anonymous request of 2026-08-05, archived without a task. test-stdlib-17-ping (SKIP if the system forbids ICMP), recipe 149.
  • TLS and the HTTP client on Windows, first part (Ottavio's decision: static OpenSSL + the Windows certificate store's CAs): os_sys_root_certs reads the «ROOT» store and tls.c adds those CAs to OpenSSL; tls_*, https_* and http_get/post/request leave the win32 gate. Written, not compiled: linking vcpkg's OpenSSL and verifying it are W5 Task 4, on the laptop. Nothing changes on Linux.
  • CHANGELOG.en.md, the English CHANGELOG from 0.33.0 (Ottavio's decision): published at nyxlang.com/changelog/. Each release translates its entry: release-check.sh refuses to cut without it and the new check 13 of make docs-health requires the same headings, subsections and items per version.

Changed

  • task_cancel is cooperative (Ottavio's decision; W5 spike §5): it requests cancellation and the task checks it with the new builtin task_cancelled() -> bool (Go's ctx.Done()); sleep() inside a cancelled task returns at once. Before, it was pthread_cancel on Linux (a task that only allocates kept running forever; 200 of them brought WSL down) and TerminateThread on Windows (it could leave the GC lock held and hang the process, 4 out of 5); both skipped defer. Behavior change: a task that neither checks nor sleeps is no longer stopped. test-513 with the spike's scenarios.

Fixed

  • NYX1047: for x: dyn Trait in arr and let y: dyn Trait = arr[0] over an Array of concrete structs passed nyx check and died with SIGSEGV (anonymous report of 2026-09-08, archived without a task): turning into dyn changes the representation when the element is WRITTEN, and reading a struct as a fat pointer crashes. It is now an error asking for Array<dyn Trait>; an untyped Array full of already-dyn values keeps working (test-391). Residue: an Array that arrives filled from another function is not detected. 3 cases in test-errors.
  • win32: runtime/csv.c joins the subset (test-141 had not linked since e0a02263; the laptop's patch). TerminateThread left os_thread_cancel (it could hang the GC, 4 out of 5) and was superseded the same day by cooperative cancellation (see «Changed»).
  • x86_64 on WSL2 (W5 spike): nyx_ev_pipe_write_fd (test-161 assumed pipe() gives consecutive fds and WSL inherits an fd 5), the «connection refused» tests are skipped with a notice when loopback does not refuse (mirrored mode), and run_stack_frame_audit.sh has per-architecture ceilings.
  • std/smtp with a «Name <address>» sender or recipients: the envelope went out as MAIL FROM:<Shop <sales@x.com>> (a real server rejects it), the Message-ID took x.com> as its domain and an accented name traveled as raw UTF-8 in From. Now MAIL FROM and RCPT TO carry only the address, the Message-ID uses its domain and the display name of From/To goes out in RFC 2047 when it is not ASCII (without the quotes around it). New test test-stdlib-13-smtp-remitente-nombre.
  • The std/postgres pool cleans the session and replaces dead connections: pg_pool_put only did ROLLBACK, so a SET, a temp table or a LISTEN leaked to the next request, and a connection cut by the server went back to the pool and was handed out broken again and again. It now does ROLLBACK + DISCARD ALL and, if that fails, closes the connection and empties the slot (the next get reconnects). New pg_pool_discard. Points 3 and 4 of the 2026-09-27 request. tests/postgres/10-pool-sanea.nx.
  • wcwidth gives 2 for wide emoji (U+270A, U+231A...): __ucs_wide is now exactly Unicode 15's East Asian Width W/F. html_unescape knows the 253 HTML 4.01 entities (before, ~50) and &#0; gives U+FFFD instead of a 0 byte. Anonymous requests of 2026-07-31, archived without a task. New cases in test-302/test-303.

0.38.0 2026-10-26

MINOR: new API for processing tabular data: the columnar reader try_csv_read in std/csv and string_to_X_range. In addition, an integer that does not fit in 64 bits is now invalid instead of saturating: string_to_int on such a number now aborts (before, it silently gave INT64_MAX).

Migration: if your code checks that the text is only digits and then calls string_to_int, a number of 19+ digits that arrives from outside now aborts the process (before, it saturated). The way out is string_to_int_or(s, def) or rejecting the overflow beforehand. Today this affects nyx-kv (INCRBY, LRANGE, SCAN, SET … EX, INCR), nyx-db (LIMIT/OFFSET), nyx-proxy (max-age) and the kv webhook: do not recompile them with 0.38.0 until they have their fix (filed in TASKS.md).

Added

  • string_to_int_range(s, ini, fin, def) / string_to_float_range(s, ini, fin, def): parse the number in bytes [ini, fin) of s without creating the substring; they always yield the same value as string_to_X_or(s.substring(ini, fin), def). Reason: in a 5M-row CSV, split() + string_to_float per row makes ~11 GC allocations per row and takes half the time (bench 2026-10-25 against Python/pandas/polars). Pre-sizing the split() Array was tried earlier and discarded: −4% on the giant split, +4..9% on the short ones. +1 test (507), recipe examples/by-example/145-csv-sin-split.nx.
  • std/csv: columnar reader try_csv_read(texto, esquema, opts): parses in a single pass straight into typed columns (int, float, str, and cat = codes + dictionary), with the core in the new runtime/csv.c (RFC 4180: quotes, line breaks inside quotes, CRLF, BOM). Strict: an invalid value is an Err with row and column. try_csv_guess_schema proposes the schema. In the 5M-row bench, grouping and filtering takes 0.93 s and 265 MB, against 1.21 s for pandas and 1.19 s for polars with one thread (with split() + Map: 5.5 s). +1 test (509), +1 C suite (test_csv.c), recipe 146-csv-columnar.

Changed

  • An integer that does not fit in 64 bits is invalid, not saturated: string_to_int aborts with its own message, string_to_int_or/_range return the default, and an int column of try_csv_read gives Err (“does not fit in an int” («no entra en un int»)). Before, strtoll left it at INT64_MAX/MIN and nobody checked ERANGE: string_to_int_or("99999999999999999999", 0) silently gave 9223372036854775807 (Ottavio's decision). Consequences that were fixed along with the change: std/json stores such an integer as "float" with its text (before, it saturated it; with the change it would have aborted the process on a number coming from outside), and the interpreter/REPL applies the same NYX2015 rule as the compiler: -9223372036854775808 gives exact INT_MIN (it gave -9223372036854775807) and a literal that does not fit is an error (it gave INT_MAX). +2 tests (510, 511), +1 C suite (test_int_parse.c), +2 checks in the REPL smoke test.
  • string_to_float / _or / _range parse with the Clinger fast path: a number [+-]digits[.digits] of up to 15 digits is converted with one exact division, which gives the same double as strtod bit for bit; the rest (exponents, 16+ digits, inf, hex, whitespace) still goes to strtod. Verified against strtod on 5M random values and on the edge cases (test_float_parse.c). In the bench of 5M rows, indexOf + _range drops from 2.67 s to 2.13 s. +1 test (508), +1 C suite.

0.37.0 2026-10-22

MINOR: two warnings from 0.36.x become errors, as announced (rule 7 of docs/VERSIONING.md): NYX1010 between integer and String, and NYX1045 on an unknown escape. Everything else is additive: std/pdf_render, chunked HTTP responses, wildcard SNI, http_serve_en, DNS records, nyx build -j N and several improvements to std/pdf, std/xlsx, std/image and std/smtp. Before the cut, 1201 files were reviewed (nyxerp, the products, the sites, and std, examples and compiler of this repo) with the 0.36.x compiler: not a single case of the two warnings.

Changed

  • NYX1010 between integer and String is an error (a warning in 0.36.x). 5 + "a", 5 == "5" and "a" < 5 compiled and died with SIGSEGV when the line ran; now they do not compile, with the same hint (int_to_string, string_to_int_or). The three test-nyx1010-*-mixto cases move to the error list of run_error_tests.sh. It is still a warning when one side reads a slot (dst[1] == "dos"): the inferred element type of an Array can lie (var dst = [9] and then dst.push(src[1]) with a String) and the slot carries its tag, so that program works (test-323, case 6; warning in test-nyx1010-casilla-aviso).
  • NYX1045 on an unknown escape is an error (a warning in 0.36.x). "\q" or "\e" were worth the letter without the backslash; now the analysis rejects them with the line and the list of valid escapes (\x1b instead of \e). It comes out with the format and NDJSON of the other analysis errors ("severity":"error").

Added

The playground moves to 127.0.0.1:8081: in production it was left open directly even though the gateway serves it (server order, 2026-10-21). Test test-505-http-serve-en (binds 127.0.0.2 and checks that 127.0.0.1 does not connect).
  • Wildcard SNI in the TLS server: tls_server_add_cert("*.dominio", cert, key) covers one label (a.dominio, not dominio nor a.b.dominio, RFC 6125), exact names win over the wildcard regardless of order, the comparison is no longer case-sensitive and the cap goes up from 16 to 64 domains. Request from nyxerp (phase C0 of its automatic onboarding of customers <cliente>.nyxerp.com). Test test_sni_name_matches (runtime) and real handshake verified with openssl s_client.
  • std/http: reading a response in chunks (nyxerp friction 20261019-200016-team-1: forwarding to the browser each chunk of a language-model API as soon as it arrives). try_http_stream_opts(method, url, headers, body, http_stream_opts()) → HttpStream, which returns with the status and the headers:
    • read() gives body chunks without the chunked framing; read_event() gives text/event-stream events already assembled (SseEvent { evento, datos, id }, WHATWG).

    • sse_wait_room(room, ms) in std/serve closes the forwarding race: the channel enters the room after the handler returns, and without waiting the first events were lost.
    • Test test-504-http-stream (split chunked, Content-Length, until close, split SSE, deadlines, gzip, disconnects, TLS), tests/ai-first/42, recipe 144-reenviar-eventos.
  • std/pdf_render: drawing a PDF page as an image (nyxerp friction 20261019-080021-team-1: tracing, in the format editor, the preprinted sheet that the print shop sends as a PDF). New module in pure Nyx: the same code on native and on wasm32-wasi, with the image byte for byte identical on both.
    • pdf_open(bytes, pdf_open_limits()) -> Result<PdfDoc, Error>, doc.page_count(), doc.page_size(p), doc.render(p, ppp, pdf_render_strict()) and doc.render_report(...) with pdf_render_best_effort(), which returns the image and the list of what was omitted. Shortcut pdf_page_to_image(bytes, página, ppp). The output is the Image of std/image.
    • Parser with classic xref, xref streams, object streams, incremental updates and reconstruction by sweeping; Flate filters (with predictors), LZW, ASCIIHex, ASCII85 and RunLength.
    • Antialiased rasterizer (exact horizontal coverage × 4 subsamples), nonzero and even-odd, strokes with joins, caps, dashing and stroke adjustment, and clipping.

  • nyx build -j N: [lib] units are compiled in parallel (nyxerp friction, 2026-10-17). Before, they ran serially: 302 modules and about 50 minutes cold on 4 cores. Fixed

  • A header written as "Nombre: valor" in a single element reaches the request (silently-wrong, nyxerp friction). The std/http client only read [nombre, valor] pairs and dropped it without warning; now it accepts both forms, also mixed (a header name cannot contain :, so there is no ambiguity with values like Bearer a:b). Test tests/ai-first/43.
  • CAPABILITIES.md lists public types and their methods: until now only free functions, so APIs made of methods (doc.render(), s.read(), d.text()) and their structs did not appear (nyxerp friction, 2026-10-20).
  • NYX1017 suggests the call when the name is a method: s.status on an HttpStream now says “'status' is a method: call it with parentheses, .status()” (nyxerp friction, 2026-10-20). Test test-nyx1017-metodo-sin-parentesis.
  • String literals compile in linear time. The lexer and escape_string concatenated one byte at a time: a 64 KB literal took ~4 s in the frontend and a 400 KB one, 32 s. Now 64 KB takes 35 ms. test-lexer and test-emit-bytes-global pin it.
  • A float from a slot without <T> keeps its value when assigned and when pushed . x = d[i] with x: float already declared, and b.push(a[2 * i]), silently gave the bits of the double as a number (1.5 → 4.6e18). Test test-502.
  • wasm32: a slot passed directly to an impl method. With an Array or String parameter, the call emitted the raw i64: on native it worked by chance, on wasm32 it was an unreachable trap. Now it is converted, just like in free functions. Test test-wasm-58.
  • Single-line enum variants no longer depend on the import path (nyxerp friction, 2026-10-18). std/pdf declares pub enum PdfFont { Helvetica, … } on one line; when it arrived first through a transitive import, the line-by-line scan in semantic looked for the variants on the following lines and registered garbage. Since the first registration wins, PdfFont.Helvetica gave NYX2012 “has no variant” (the NYX2012 check in expressions, new in this version, made it visible; before, it failed in codegen with “unknown enum variant”). With the imports reversed it compiled. Regression: test-498.
  • std/smtp verifies against the system CAs (nyxerp friction, 2026-10-18). smtp_starttls (587) and smtp_connect_tls (465) verified against the tls_set_ca_file store, which starts empty: every public relay with a valid certificate gave “unknown ca”. The workaround, tls_set_ca_file(""), added all the public CAs to a global store that the verify-ca of std/postgres also uses. Now they use tls_upgrade_fd_verified_system / tls_connect_verified_system, as std/imap already did. Verified against smtp.gmail.com on 587 and 465: before, both failed; now they verify. The self-signed one is still rejected (test-stdlib-07, case d). The workaround is no longer needed; a per-connection private CA is filed.
  • A slot of an Array without <T> passed directly to a struct parameter, or used as a Map key, now works (nyxerp friction, 2026-10-17). texto(hs[0]), with fn texto(h: Hoja), passed the raw i64 of the slot where the function expected the struct by value. The result was “GC heap exhausted” or, in another nyxerp program, the function received a different element. m.insert(pares[0], pares[1]) used the i64 as the key pointer and clang rejected the IR. In both cases nyx check was green. Now the slot is converted to the parameter's struct (inttoptr + load, as in let h: Hoja = hs[0]), and the key of a Map method that comes from a slot is read as a String. The compiler itself had the same pattern in cg_tipo_duplicado(decls[i], …), which worked by chance thanks to the aarch64 calling convention. ASTNode is left out: in a slot it is an Array, not a pointer. Regression: tests/ai-first/40-casilla-sin-tipo-como-argumento.nx and gotcha untyped-slot-as-argument.
  • nyx check rejects an enum variant that does not exist (NYX2012) (nyxerp friction, 2026-10-17). PdfFont.Zzzz passed the check in green and only codegen rejected it, with a message that asked for a type annotation. Now it is NYX2012, with “did you mean” if there is a close variant, for both local and imported enums. It is not validated when the name corresponds to a variable or a parameter. Cases test-nyx2012-variante-{inexistente,importada}.
  • String escapes: \xNN and \u{…} are worth what they say, and an unknown escape warns (NYX1045) . Before, the lexer knew only \n \t \\ \" \r \0 and any other escape silently lost the backslash: "\x41" was worth x41, "\u{0}" was worth u{0} and '\x41' printed 41.   • The compiler no longer runs out of stack on long expressions: from 52 to ~2.400 operands with the default stack. The cause, measured with clang -fstack-usage: the toolchain is linked at -O0 and each level of an expression stacked ~151 KB of codegen frames. Three pieces: (1) codegen_binop and codegen_expr split so that the recursion goes through small frames —a pure refactor, identical IR in 524 files— (151 → 23 KB per level, ceiling 322); (2) SROA over the seeds when there is an opt of the same version as clang, +2 s per bootstrap (23 KB → 2 KB per level, ceiling ~2.400; without opt, 322); (3) the main thread's stack overflow has a name: infinite recursion in main prints «main thread stack overflow» («desborde de pila del hilo principal») with the limit, instead of a mute «Segmentation fault» (POSIX; Windows is left for W4). New guard run_stack_frame_audit.sh in make test-ai-first, a ratchet on the frames of the recursive path. The floor that remains is CodegenContext by value: its root is the draft arc structs-byval.

Measured cause: the toolchain is linked without -O and each level of a binary expression stacks ~151 KB of codegen frames (codegen_binop alone, 132.880 B at -O0 against 1.488 B at -O2), so 53 levels exhausted the default 8 MB.   • semantic was QUADRATIC in the size of the closure: the symbol and signature tables were walked whole, comparing strings. scope_lookup and fn_sig_index scanned the whole of g_sym_names and g_fn_sig_names on every query. Since the resolver inlines the import closure into a single translation unit, those tables grow with the number of modules while the number of lookups grows with the volume of code: the product is the quadratic. Now there is a per-name index (Map<String,int> + a parallel array that chains homonyms in declaration order) over the two tables, and the other six consumers —scope_get_arity, lookup_var_type, name_is_builtin, fn_es_privada_de, fn_module_resolve, scope_has_in_current— walk the name's chain instead of the table.

  • Writing over TLS to a peer that had already closed KILLED THE PROCESS with SIGPIPE . OpenSSL writes with a raw write() and this runtime deliberately does not install a global SIG_IGN for SIGPIPE (os_sock_send protects itself with MSG_NOSIGNAL, and its comment states that this is «load-bearing»), so the TLS layer was left without that protection: a tls_write_conn against a departed peer killed the entire process. runtime/tls.c now uses its own BIO that writes through os_sock_send, instead of ignoring the signal at runtime startup —which would have changed the semantics of every program that links Nyx, nyx prog | head included—. The 5 SSL_set_fd calls in the file go through tls_attach_fd, with the same contract (BIO_NOCLOSE: the caller closes the fd) and without depending on the BIO_meth_get_*, deprecated since OpenSSL 3.5.

    Why only now: in a normal HTTP response the window between «the client closed» and «the server writes» is milliseconds.
