0.42.0 2026-11-08

MINOR: new nyx build targets built from Linux — Android/Termux (aarch64-linux-android, a bionic PIE that runs without proot) and the Windows x86_64 .exe (win-cross) —, native nyx build on Windows and an .exe that runs as a service, std/rsa with X.509 certificates, cyclic imports that work in build, check and [lib], and the silently-wrong cases nyxerp found in real use: a slot of an untyped Array read as a struct/enum (NYX2022 instead of SIGSEGV or garbage), crc32_bytes of a String and for x in xs without <T>.

Migration: a program that passed a slot of an untyped Array holding something else (a row, a String) to a struct/enum parameter now aborts with NYX2022 instead of segfaulting or reading garbage: annotate Array<T> or convert the slot before passing it. NYX_SLOT_CHECK=off turns the guard off while migrating.

Fixed

  • crc32_bytes(xs[i]) with a slot of an untyped Array emits valid IR (the String crc32 fix of 11-05 numbered the result temporary before the slot's inttoptr; caught by run_builtin_arg_opaco.sh). The crc32 branch moves out of codegen_call_expr into emit_crc32_bytes: inline it had raised its -O0 frame 1760 B above the ceiling; it now sits at 472064 B (ceiling lowered in run_stack_frame_audit.sh).
  • A slot of an untyped Array that goes to a struct or enum is read by its tag: NYX2022 instead of SIGSEGV or garbage (silently-wrong, nyxerp friction 20261108). Passing a[0] (or the variable of a for over a) to a Caja or Valor parameter compiled and passed nyx check; at run time a struct gave SIGSEGV and an enum read the discriminant of another structure and the match entered no arm (empty output, exit 0). Now, in the destinations call or method argument, let x: T, x = …, return and for p in a, if the slot's tag proves it is not a struct/enum (int, String, float, bool, Array, Map) the program aborts with NYX2022 naming the expected and the found type (rc 1). UNKNOWN and PTR pass: the legitimate pattern a.push(caja); leer(a[0]) does not change (the 5 stacks green). It is turned off with NYX_SLOT_CHECK=off. Not covered yet: the field of a struct literal (S { c: a[0] }) and for p: Caja in a (ticket in TASKS.md). Tests: test-541, the error test slot-sin-tipo-leido-como-struct-enum-abort and ai-first 53.
  • Cyclic imports: two modules that import each other (a ↔ b), or a module that imports the main one back, compile and check just the same in nyx build, in nyx check on either file and with [lib] modules (nyxerp friction 20261106). They were already valid by design (the resolver inlines each path only once), but there were two bugs alongside: the type scan of an import read the fields of a ONE-line struct on the following lines, and with the cycle it gave false NYX1017/NYX1032 («missing fields: pub»); and the main file did not count as already imported, so nyx check src/m/a.nx re-inlined it and gave NYX1040. Along the way, pub struct Id(int) in an imported module exported the name «Id(int)» and broke the parse (NYX0101). Guards: Check R of run_tooling_gates.sh (+5) and 3 cycle cases in run_lib_modules.sh.
  • crc32_bytes(s) with a String gave a different number on each call (silently-wrong, nyxerp friction of 2026-11-05, the site's visual editor). The builtin expected an Array of bytes, the checker did not look at the type and codegen handed over the %nyx_string* as if it were an array: the runtime read the String's struct as an array and walked over garbage. Now a String goes to nyx_crc32_string (the CRC-32 of its bytes, same table; "123456789" → 3421780262), an Array continues as before, and an int/float/bool is NYX1031 with a hint. Tests 531 and test-nyx1031-crc32-bytes-int; line in LLM.md.
  • nyx build sweeps its orphaned temporaries (compiler/build.nx). If a build was killed (Ctrl+C, KILL, external timeout) the final borrar_arbol was never reached and its nyx_libs_<pid>_…/nyx_build_<pid>_… stayed in $TMPDIR forever (48 MB in one case measured on 2026-11-05; on the server /tmp is tmpfs). Now tmp_dir_propio first deletes the directories of that exact shape whose PID no longer exists (kill_process(pid, 0), and /proc on Linux), in pure Nyx so that it holds on Windows; what belongs to a live PID and what does not have the shape is left alone. Same recipe as nyx test. Three new checks in run_build_manifest.sh (37). Closes the LOW backlog item «nyx build interrupted with Ctrl+C».
  • nyx test respects $TMPDIR and sweeps its own orphans (compiler/test.nx). The four mktemp said plain /tmp: a suite that exported TMPDIR to avoid filling the tmpfs (nyxerp) kept leaving each file's binary in the machine's RAM, and if nyx test was killed (KILL, external timeout) the per-file sh trap did not suffice and the directory stayed forever (on 2026-10-26: 30 leftovers and ~1.3 GB of swap in /tmp pages). Now the base is $TMPDIR (or /tmp), each temporary carries its owner's PID (nyx_test_<pid>_XXXXXX, nyx_test_src_, nyx_test_libs_, nyx_cov_) and the next run deletes those of dead PIDs; what belongs to a live PID and the names of the old format are left alone. The paths of the generated script are now quoted (a TMPDIR with a space failed). A nonexistent TMPDIR gives a clear error instead of a mute FAIL. Four new checks in run_tooling_gates.sh (38). Closes the LOW backlog item of 2026-10-26.
  • for x in xs over an Array without <T> reads each slot by its tag, as xs[i] already did (silently-wrong, nyxerp report of 2026-11-04 when adopting the get_or fix). When codegen did not know the element type (a bare Array, m.get_or(k, []), a mixed literal), x was an int and print(x) / "v=" + x showed the String's address with no error. Now codegen_for rewrites the body so that each x is __arr[__idx] over two hidden variables (licm.nx walker, for_sustituir_var), and all consumers go through codegen_index_access, which consults the tag. It does not apply if the body rebinds x, mutates the traversed array or has nested fns (the old path remains); NYX_FOR_SLOT=off turns it off. Along the way, let a: Array = [1, "dos"] is no longer inferred as Array<int> from the first element: it uses the common type (tipo_comun_de_literal, like the for over a literal since 0.36.0) and a mixed literal stays a bare Array (closes the LOW backlog item of 2026-07-26). Test ai-first/52, gotcha for-untyped-slot-by-tag.
  • m.get_or(k, []) with an Array (or a Map, or a struct) stored as a value no longer produces invalid IR when the result is used unannotated (for x in m.get_or(k, []), passing it as an argument, chaining .length()). The get_or helper returned i64 for every default that was neither String nor float, and it only survived behind a let v: Array = … (which converts by the declared type); without the annotation clang rejected the IR («defined with type 'i64' but expected 'ptr'», nyxerp report of 2026-11-04, a variant of the ai-first/49 case). Now the result has the type of the default, as already happened with float (and the for over it reads by tag: previous bullet). Test ai-first/51.
  • install.ps1 fails on the spot if a process holds the previous installation (.nyx.old in use) instead of finding out after a minute of compiling and linking; the message names the step that failed and «your current install was not changed»; and it warns about NYX_HOME when installing with a -Prefix different from %USERPROFILE%\.nyx, because the driver does not look for its installation next to the executable (HIGH backlog item in TASKS.md). Patch from the laptop, W6 Task 8 round 1.

0.41.0 2026-11-02

MINOR: changes observable semantics — a closure created in a loop sees the variable of ITS iteration, as in Go 1.22: a program that printed 3 3 3 3 now prints 0 1 2 3, and spawn in a loop or a for variable inside a closure are no longer NYX1044. Also arriving: cross-compilation between Linux x86_64 and aarch64, try/catch on Windows, nyx build without bash, typing of the stdlib (Array<String> and friends in sqlite, multipart, kvclient, resp, http, args and eight other modules) and fixes for untyped Array slots that nyxerp found in real use.

Migration: (1) where the stdlib now declares Array<String> (or Array<int>), annotating an element with another type is NYX1003 instead of compiling and producing garbage: fix the annotation. (2) A local let is no longer visible before its line. (3) Code that relied on the closures of a loop seeing the last iteration must save that value outside the loop.

Added

  • New in the stdlib: find_program, host_arch and cpu_count (std/process); temp_dir, try_lock_file, try_lock_file_nowait and unlock_file (std/fs): command -v, uname -m, nproc, mktemp and flock without launching a shell, on Linux and on Windows (PATHEXT, GetSystemInfo, GetTempPath, LockFileEx). find_program searches like try_spawn: on Windows never in the current directory, and a .bat/.cmd gives None. test-525…528 (also verified as .exe on Windows).
  • Cross-compilation between Linux x86_64 and aarch64: nyx build --target x86_64-unknown-linux-gnu (or aarch64-unknown-linux-gnu, or [build] target) builds the binary for the other architecture from the same machine, in target/<triple>/<name>; the host triple compiles natively. It needs the target's multiarch libraries and lld, and if they are missing it says so before compiling, with the apt command. nyx run runs the host triple and explains why not the other; an asm with x86 register constraints gives an error with its line if the target is aarch64 (e513b498, e327192a, 0135e801). Recipe 153, gotcha cross-compile-arch, docs/DEPLOYMENT.md.
  • try/catch on the Windows target (x86_64/aarch64-pc-windows-msvc): the codegen calls _setjmp(buf, NULL), because the MSVC CRT has no setjmp, and stops rejecting try on that target (on wasm32-wasi it is still rejected). With NULL, longjmp jumps directly as in glibc, without unwinding through SEH: measured in the spike, throw costs 0.02 µs instead of 0.8. It also fixes defer and drops, which already emitted setjmp on Windows and did not link. Patch from the laptop; it joins the Windows gate with W6 Task 3.
  • std/process tests on Windows (tests/runtime-unit/win/test_os_proc_spawn_win32.c, 92 asserts, win gate): verified on the laptop on 2026-10-29 (9fcf1faf).

Changed

  • nyx build no longer writes or runs a bash script: the compiler, clang and ar are launched with std/process, and the compiler's ulimit -s is a stack limit inherited by the children. It is the preliminary step for nyx build on Windows. The automatic runtime cache changes its key once: the first nyx build after updating builds a new .a.

Fixed

  • A closure created in a loop sees the variable of ITS iteration (Go 1.22 semantics): a body let/var had ONE field in the shared environment, so four closures stored in an Array and called after the loop all read the last one (3 3 3 3 instead of 0 1 2 3), with no error. Now each iteration has its own instance (one GC box per iteration, only in functions with a nested fn inside a loop) and each lambda/spawn receives a frame with the boxes of that iteration; the body and the iteration's closures share the instance (a var mutated after the closure is created is seen by it) and variables outside the loop remain shared. As a result spawn inside a loop and a for variable are no longer NYX1044; a repeated name and match bindings still are. Observable: a program that printed 3 3 3 3 now prints 0 1 2 3. tests/ai-first/48-closure-por-iteracion .
  • a[i] == b[j] between two untyped Arrays compares Strings by content: neither side contributed a type and the raw slots were compared, so the same text in two different arrays gave false with no error. nyx_slot_eq (runtime) decides by the tags: two String slots by content, anything else raw (5 against "5" is still false). With Array<T> the static type decides, as before. tests/ai-first/47-casilla-igual-casilla.
  • m.insert(a[0], a[1]) into a Map<String> with an untyped a: Array stores the value as a String: the slot arrived as a raw i64, the Map was re-registered as Map<int> and print(m.get(k)) printed the pointer with no error (nyxerp friction). emit_map_insert_i64 respects the already registered value type.
