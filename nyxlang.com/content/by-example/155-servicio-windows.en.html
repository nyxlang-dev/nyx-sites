There is no new API for Windows services. The same .exe runs in a console or under the Service Control Manager: if the manager launched it, the runtime detects that on its own and delivers the stop (sc stop, shutting the machine down) as SIGTERM, just like Ctrl+Break in a console or kill on Linux. The program only has to handle signal 15 and finish what it is doing.

listo: 3 vueltas

signal_handle(15, al_parar) registers a handler that sets the global parar to 1. The main loop does one unit of work (sleep(100) here), so the signal never cuts it in half, and checks the flag on every turn. When it exits it writes vueltas=N to the state file and prints the count. With no arguments it is a demo that stops by itself after three turns, so the recipe can be tried without installing anything (the output above); as a service it receives the state file path as an argument and runs until it is stopped.

To install it, in PowerShell as administrator, use New-Service with -BinaryPathName holding the quoted path to the .exe and its arguments, then sc.exe failure and sc.exe start (New-Service rather than sc.exe create, which in PowerShell 5.1 breaks paths with spaces). A service's working directory is System32, so pass paths as absolute, by argument. The manager is always told the exit was clean; sc failure only acts if the process dies without exiting (a crash, taskkill /F).
