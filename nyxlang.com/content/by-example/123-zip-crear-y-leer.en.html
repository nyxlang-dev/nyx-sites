An ERP packs several reports into one .zip to attach to an email, and receives zips from outside — a bank, an accountant — that have to be opened. std/zip is pure Nyx with no zlib, so the same program runs on the server and compiled to wasm32-wasi. Everything here happens in memory; the recipe writes no files.

zip armado: 1361 bytes entrada: ventas.csv entrada: notas/lea-me.txt tiene ventas.csv contenido: Cierre de septiembre. ventas.csv: 3073 bytes descomprimidos rechazado: zip: no es un zip (falta el fin del directorio central)

zip_writer(), add(name, data) and finish() produce the bytes of the archive; each entry goes in with DEFLATE unless compressing would make it bigger. Reading is two steps: zip_read() loads the index (the central directory) and entry(name) decompresses ONE entry and verifies its CRC-32, so a corrupted entry is an error and not wrong data.

A file that arrives from outside is not read without limits: ZipReadOpts caps what a zip bomb can make the program do. And bytes that are not a zip at all come back as an Err — the last line of the output — never as half-read data.
