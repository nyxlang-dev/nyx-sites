Para entregar un programa a máquinas x86_64 y aarch64 no hace falta armarlo en cada una. nyx build --target x86_64-unknown-linux-gnu (desde un host aarch64) o --target aarch64-unknown-linux-gnu (desde x86_64) produce el binario de la otra arquitectura. También se puede fijar con [build] target = "..." en nyx.toml. La salida va a target/<triple>/<name> y no pisa el binario nativo.

corriendo en: aarch64 ok: arquitectura Linux soportada como destino

El programa le pregunta uname -m a try_spawn con la salida por pipe, junta el resultado con try_child_collect e imprime la arquitectura en la que corre; cualquier fallo cae en "desconocida". Se arma para cada destino y se comprueba la salida en la máquina correspondiente (la de arriba es de un host aarch64). El triple del propio host compila nativo; el de la otra arquitectura usa clang con --target=<triple> y lld, y el runtime de C se compila para el destino y se guarda en caché por destino. En Debian/Ubuntu hacen falta los paquetes multiarch (libc6-dev, libgc-dev, libssl-dev, zlib1g-dev, libgcc-N-dev de la otra arquitectura, más lld); si falta algo, nyx build lo dice antes de compilar, con el comando exacto.

Límites: no hay emulación, así que el binario cruzado no se ejecuta en la máquina que lo armó y nyx run --target <otra arquitectura> falla; hay que copiarlo a una máquina de esa arquitectura o probarlo en un contenedor con docker run --platform linux/amd64. El binario es dinámico: el destino necesita libgc, libssl3, libcrypto, libz y glibc. Y un asm con restricciones de una letra de x86 (a b c d S D) se rechaza cuando el destino es aarch64.
