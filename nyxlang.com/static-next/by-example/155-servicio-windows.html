A program that runs as a Windows service

There is no new API for Windows services. The same .exe runs in a console or under the Service Control Manager: if the manager launched it, the runtime detects that on its own and delivers the stop (sc stop, shutting the machine down) as SIGTERM, just like Ctrl+Break in a console or kill on Linux. The program only has to handle signal 15 and finish what it is doing.

// Nyx by Example: un programa que corre como servicio de Windows.
//
// No hay API nueva: el MISMO .exe corre en consola o como servicio. Si lo lanzó
// el administrador de servicios, el runtime lo detecta solo y le entrega la
// parada (`sc stop`, apagar el equipo) como SIGTERM, igual que Ctrl+Break en
// consola o `kill` en Linux. El programa solo tiene que manejar la señal 15 y
// terminar lo que está haciendo.
//
// Instalar (PowerShell como administrador; New-Service y no `sc.exe create`,
// que en PowerShell 5.1 rompe las rutas con espacios):
//
//     New-Service -Name MiTrabajo -StartupType Automatic `
//       -BinaryPathName '"C:\Program Files\MiTrabajo\trabajo.exe" "C:\ProgramData\MiTrabajo\estado.txt"'
//     sc.exe failure MiTrabajo reset= 86400 actions= restart/1000
//     sc.exe start MiTrabajo
//
//   - El directorio de trabajo de un servicio es System32: las rutas van
//     absolutas, por argumento.
//   - Al SCM siempre se le informa salida limpia; `sc failure` actúa solo si el
//     proceso muere sin salir (crash, taskkill /F).

import "std/fs"

var parar: int = 0

fn al_parar(sig: int) -> int {
    parar = 1
    return 0
}

fn main() -> int {
    let args: Array = get_args()
    // Sin argumentos es una demo que termina sola (3 vueltas), para probar la
    // receta sin instalar nada. Como servicio recibe la ruta del estado y corre
    // hasta que lo paren.
    var estado: String = temp_dir() + "/nyx-servicio-demo.txt"
    var max_vueltas: int = 3
    if args.length() > 1 {
        estado = args[1]
        max_vueltas = -1
    }

    signal_handle(15, al_parar)

    var vueltas: int = 0
    while parar == 0 and (max_vueltas < 0 or vueltas < max_vueltas) {
        sleep(100)          // una unidad de trabajo; la señal no la corta a la mitad
        vueltas = vueltas + 1
    }
    write_file(estado, "vueltas=" + int_to_string(vueltas))
    print("listo: " + int_to_string(vueltas) + " vueltas")
    return 0
}
Outputstdout
listo: 3 vueltas

How it works

signal_handle(15, al_parar) registers a handler that sets the global parar to 1. The main loop does one unit of work (sleep(100) here), so the signal never cuts it in half, and checks the flag on every turn. When it exits it writes vueltas=N to the state file and prints the count. With no arguments it is a demo that stops by itself after three turns, so the recipe can be tried without installing anything (the output above); as a service it receives the state file path as an argument and runs until it is stopped.

To install it, in PowerShell as administrator, use New-Service with -BinaryPathName holding the quoted path to the .exe and its arguments, then sc.exe failure and sc.exe start (New-Service rather than sc.exe create, which in PowerShell 5.1 breaks paths with spaces). A service's working directory is System32, so pass paths as absolute, by argument. The manager is always told the exit was clean; sc failure only acts if the process dies without exiting (a crash, taskkill /F).
