Run an external program

try_spawn(argv, opts) starts a child process and returns a Child. argv is an Array: there is no shell in between, so there are no quotes, * or $VAR to escape. spawn_opts() leaves stdin, stdout and stderr inherited, so the child writes to the same terminal as the parent. try_child_wait blocks until the child exits and returns its exit code.

// Lanzar un programa externo — std/process
// Run an external program — std/process
//
// try_spawn lanza el hijo SIN fork, así que el mismo código es portable.
// argv es un Array (sin shell: nada de comillas ni `*`), y si el
// programa no existe el lanzamiento da Err(not_found) en vez de un hijo que
// sale con 127.
//
// Nota: los builtins crudos fork/execvp/waitpid/dup2/pipe_new/kill_process
// siguen disponibles en posix tal como siempre; donde no hay fork, el
// compilador los rechaza y apunta a std/process. Esta receta usaba fork +
// execvp + waitpid.
// EN: raw fork/execvp/waitpid remain available on posix; std/process is the
// portable replacement.

import "std/process"

fn main() -> int {
    // Todo heredado: el hijo escribe en la misma terminal que el padre.
    let opts: SpawnOpts = spawn_opts()
    match try_spawn(["echo", "hello from child"], opts) {
        Result.Ok(c) => {
            if child_pid(c) > 0 { print("parent: spawned child") }
            match try_child_wait(c) {
                Result.Ok(code) => { print("parent: child exited with " + int_to_string(code)) }
                Result.Err(e) => { print("wait failed: " + e.msg) }
            }
        }
        Result.Err(e) => { print("spawn failed: " + e.msg) }
    }

    // Un programa inexistente falla al lanzar.
    match try_spawn(["nyx-no-such-program-xyz"], opts) {
        Result.Ok(_c) => { print("unexpected: it ran") }
        Result.Err(e) => { print("not found: " + e.kind) }
    }
    return 0
}

How it works

The parent and the child write at the same time, so the order of the first two lines can change from run to run; the exit code always comes after, because try_child_wait waits for the child.

A program that does not exist fails at launch: try_spawn returns Err with kind not_found and e.stage == "exec". With raw fork + execvp the parent saw no error and the child exited with 127; if your code relied on that, map not_found to 127 yourself.

The raw builtins fork, execvp and waitpid are still available on posix, unchanged. std/process is the portable way, and it needs no care with the garbage collector: there is no forked copy of the parent.
