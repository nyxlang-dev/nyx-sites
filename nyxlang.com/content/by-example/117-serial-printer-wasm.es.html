Una impresora de punto de venta habla ESC/POS por puerto serie: un puñado de bytes de control para iniciar, cortar y abrir la gaveta de dinero, con texto plano en el medio. std/browser_serial la alcanza directo desde wasm32-wasi con await, sin pasar por el diálogo de impresión del sistema — el paso más lento de una venta, y uno que no puede cortar el papel ni abrir una gaveta. Los bytes cruzan como Array<int>, nunca como String: un String cruzaría el shim por TextEncoder/TextDecoder y corrompería en silencio los bytes de control que no son UTF-8 válido.

ticket impreso: 33 bytes

armar_ticket arma a mano cuatro comandos ESC/POS: ESC @ resetea la impresora, el texto del ticket sigue byte a byte (un String de Nyx ya es bytes — ver el gotcha en LLM.md §5), y después GS V 66 0 corta el papel y ESC p 0 25 250 pulsa el pin de la gaveta. Nada acá es codificación de texto: es la secuencia exacta de bytes que espera el firmware de la impresora.

serial_authorized_ports() se prueba PRIMERO, así un cliente que vuelve reconecta sin diálogo de permiso; serial_request_port(), que sí lo muestra, queda como respaldo para la primera visita. serial_read(p, max, timeout_ms) —no se usa en un ticket de solo impresión, pero hace falta para la respuesta de una impresora fiscal— puede devolver menos de max bytes cuando se cumple el plazo habiendo llegado al menos uno: una respuesta corta de la impresora sigue siendo válida, no es un error.

Sin Web Serial —Firefox, Safari, o una página servida sin HTTPS/localhost— toda la cadena de llamadas devuelve Err(kind: "io"), que es exactamente la señal que usa main para caer a la impresión del sistema en vez de perder la venta: "no se pudo imprimir por serial (io): volver a impresión del sistema". WebUSB, para impresoras que solo exponen esa interfaz, queda para una fase posterior.
