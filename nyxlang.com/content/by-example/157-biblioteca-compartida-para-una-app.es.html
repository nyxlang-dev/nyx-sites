Un programa Nyx puede armarse como lib<nombre>.so en vez de un ejecutable, para que otra cosa lo cargue: una app Android por JNI, un programa en C con dlopen, Python con ctypes. Se arma con nyx build --shared (salida target/lib<nombre>.so), se agrega --target aarch64-linux-android para Android, o se fija con [build] kind = "shared" en nyx.toml.

hola, app

Aquí echo se exporta con #[export_name("app_echo")] y llamadas como app_llamadas; init reinicia un contador global. Como programa normal, main llama a init, llama a echo("hola, app"), verifica el resultado y el contador con assert e imprime hola, app. Ese main existe solo para que la receta se pueda ejecutar: en modo --shared se borra, porque una .so con fn main es el error NYX1049.

Las reglas del modo: solo las funciones con #[export_name] salen de la .so, con ese nombre C; todo lo demás queda oculto, también los pub. Su firma usa solo int (int64_t), float (double), bool, punteros crudos y String; cualquier otro tipo es NYX1048. Un String entra como (const uint8_t *ptr, int64_t len), bytes UTF-8 que pueden traer NUL, y sale como un nyx_buf * reservado con malloc fuera del GC, que quien llama libera con nyx_buf_free. Un fn init() opcional corre una sola vez, al cargar la biblioteca. El estado de larga vida (una conexión, un servidor) se guarda del lado de Nyx y se entrega al llamador como un int opaco que él devuelve en cada llamada.

Límites importantes: un assert fallido, un panic, la falta de memoria o un NYX2022 dentro de la .so matan la app anfitriona entera, sin recuperación; los errores esperables se devuelven como códigos o buffers. Se carga una sola .so de Nyx por proceso, porque cada una trae su propio GC y runtime, y nunca se llama una exportada desde el hilo de UI, porque corre en el hilo del llamador y lo bloquea; se usa un hilo propio. El directorio templates/android del repo del lenguaje trae el shim JNI y un puente en Kotlin para copiar a un proyecto Gradle.
