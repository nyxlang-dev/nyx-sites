Cross-compiling between Linux x86_64 and aarch64

To ship one program to both x86_64 and aarch64 machines you do not need to build on each one. nyx build --target x86_64-unknown-linux-gnu (from an aarch64 host) or --target aarch64-unknown-linux-gnu (from x86_64) produces the binary for the other architecture. You can also set [build] target = "..." in nyx.toml. The output goes to target/<triple>/<name> and does not overwrite the native binary.

// Nyx by Example: compilación cruzada entre Linux x86_64 y aarch64.
//
// Un mismo programa se arma para la otra arquitectura sin tocar el código:
//
//     nyx build --target x86_64-unknown-linux-gnu      # desde aarch64
//     nyx build --target aarch64-unknown-linux-gnu     # desde x86_64
//
// (o `[build] target = "..."` en nyx.toml). La salida va a target/<triple>/<name>
// y no pisa el binario nativo. El triple del propio host compila nativo; el de la
// otra arquitectura usa clang con --target=<triple> y lld, y el runtime de C se
// compila para el destino (cacheado por destino).
//
// Requisitos (Debian/Ubuntu, multiarch; ejemplo aarch64 -> x86_64):
//     sudo dpkg --add-architecture amd64 && sudo apt update
//     sudo apt install libc6-dev:amd64 libgc-dev:amd64 libssl-dev:amd64 \
//         zlib1g-dev:amd64 libgcc-14-dev:amd64 lld
//   (libgcc-N-dev: N es la versión de gcc de la distro; al revés, usa :arm64.)
// Si falta algo, `nyx build` lo dice antes de compilar, con el comando exacto.
//
// Límites:
//   - No hay emulación: el binario cruzado no se ejecuta en la máquina que lo arma
//     (`nyx run --target <otra arquitectura>` falla); cópialo a una máquina de esa
//     arquitectura, o pruébalo en un contenedor `docker run --platform linux/amd64`.
//   - El binario es dinámico: la máquina destino necesita libgc, libssl3, libcrypto,
//     libz y glibc.
//   - `asm` con restricciones de una letra x86 (a b c d S D) se rechaza con destino
//     aarch64; la plantilla de ensamblador siempre es del usuario.
//
// Este programa imprime la arquitectura en la que corre: compílalo para cada destino
// y comprueba la salida en la máquina correspondiente.

import "std/process"

fn arquitectura() -> String {
    var o = spawn_opts()
    o.stdout = Stdio.Pipe
    match try_spawn(["uname", "-m"], o) {
        Result.Ok(c) => {
            match try_child_collect(c) {
                Result.Ok(r) => { return r.stdout.trim() }
                Result.Err(_) => { return "desconocida" }
            }
        }
        Result.Err(_) => { return "desconocida" }
    }
    return "desconocida"
}

fn main() -> int {
    let a = arquitectura()
    print("corriendo en: " + a)
    if a == "x86_64" || a == "aarch64" {
        print("ok: arquitectura Linux soportada como destino")
    }
    return 0
}

How it works

The program asks uname -m through try_spawn with stdout piped, collects the result with try_child_collect and prints the architecture it is running on; every failure falls back to "desconocida". Build it for each target and check the output on the matching machine (the output above is from an aarch64 host). The host's own triple compiles natively; the other architecture uses clang with --target=<triple> and lld, and the C runtime is compiled for the target and cached per target. On Debian/Ubuntu you need the multiarch packages (libc6-dev, libgc-dev, libssl-dev, zlib1g-dev, libgcc-N-dev for the other architecture, plus lld); if something is missing, nyx build says so before compiling, with the exact command.

Limits: there is no emulation, so the cross-built binary does not run on the machine that built it and nyx run --target <other architecture> fails; copy it to a machine of that architecture or try it in a container with docker run --platform linux/amd64. The binary is dynamic, so the target needs libgc, libssl3, libcrypto, libz and glibc. And asm with x86 one-letter constraints (a b c d S D) is rejected when the target is aarch64.
