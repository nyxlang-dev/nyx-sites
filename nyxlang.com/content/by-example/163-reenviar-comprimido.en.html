A proxy written in Nyx repeats the browser's request against a server behind it and returns the response. If that server already compresses, the cheap thing is to pass those bytes through: decompressing only to compress again costs CPU and memory. The recipe runs on its own: a thread plays the server behind and compresses with zip_gzip.

estado: 200 Content-Encoding: gzip bytes recibidos: 159 bytes al descomprimir: 10400

By default try_http_stream_opts answers Err(unsupported) to any Content-Encoding, because read_event() cannot split a compressed body into lines. With opts.cuerpo_crudo = true the response is accepted: read() delivers the compressed bytes, headers() shows Content-Encoding, and read_event() is the one that gives Err(unsupported). The clients that return the whole response, try_http_request and try_http_request_opts, never decompress.

In a server built on std/serve the full forward is three steps: pass the client's Accept-Encoding to the request behind, open with cuerpo_crudo, and return response_from_stream(s), which copies Content-Encoding and Vary along with the rest of the content headers. The output shows the bytes received and what they decompress to: they are the origin's gzip, untouched.
